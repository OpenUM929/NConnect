03. 중력 만져보기

지구에서 손에 쥐고 있던 공을 놓으면 순식간에 바닥으로 떨어져요. 달에서도 그럴까요? 크기와 무게가 같은 공을 지구와 달에서 같은 높이로 떨어뜨리면 결과가 어떻게 나올지 Isaac Sim에서 직접 확인해봐요.

①

생각 열기

지난 강에서는 Isaac Sim에서 공을 생성하여 떨어뜨리는 것까지 실습해 보았어요. 그런데 공이 떨어지는 움직임은 누가, 어떻게 계산하는 걸까요?바로 화면 뒤에서 쉬지 않고 일하는 물리 엔진이에요. 이번 강에서 그 엔진을 직접 들여다봐요.

PhysX, 시뮬레이션의 심장

Isaac Sim 안에는 PhysX라는 물리 엔진이 들어 있어요. 엔비디아가 오래 개발해온 상업용 엔진으로, 지금 이 순간에도 전 세계의 게임과 시뮬레이션에서 돌아가고 있어요. PhysX가 계산하는 물리 현상은 네 가지예요. 중력, 충돌, 관성과 마찰이에요. 이걸 1초에 60번 넘게 계산하죠. 이 네 가지가 어떻게 다른지, 아래에서 하나씩 살펴봐요.

힘을 고르고 "▶ 있을 때 / ▶ 없을 때"를 눌러보세요.
게임을 하면 컴퓨터가 서서히 뜨거워지는 데엔 다 이유가 있어요. 움직이는 게임 화면을 실시간으로 만들어내면서, 그 뒤에선 여러 물리 현상들을 1초에 수십 번씩 쉬지 않고 계산하거든요.

400년 전, 갈릴레이가 던진 질문

1589년 피사의 사탑 위에서 무슨 일이 있었는지는 정확한 기록이 없어요. 다만 갈릴레이는 평생 비슷한 가설을 끈질기게 주장했어요. "공기 저항이 없다면, 무거운 것과 가벼운 것은 같은 속도로 떨어진다."라고요.당시 사람들은 갈릴레이의 주장을 믿지 않았어요. 깃털과 망치를 같이 떨어뜨려보면 누가 봐도 망치가 먼저 땅에 닿거든요. 이 가설은 공기를 뽑아낸 유리관 안에서 깃털과 납덩이가 나란히 떨어지는 걸 보고서야 결판이 났어요. 갈릴레이가 세상을 떠난 뒤의 일이에요.

갈릴레이가 옳았는지 보려면 공기 저항이 없는 진공이 필요해요. 현실에선 진공 상태를 만들기 어렵지만, Isaac Sim에서는 코드 한 줄이면 돼요. 무게와 상관없이 정말 같은 속도로 떨어지는지 잠시 뒤 확인해요.

③

개념 만나기

중력 가속도를 바꾸는 코드는 딱 한 줄이에요. 어떤 코드를 수정하면 되는지 함께 찾아봐요.

중력을 다루는 PhysicsContext

중력은 PhysicsContext가 담당해요. 물리 설정을 모아 두는 곳이거든요. 쓰는 법도 간단해요.

중력 설정하기
world.get_physics_context().set_gravity(-9.81)
지구의 중력 가속도는 9.81 m/s²예요. Isaac Sim에서 Z축은 양수가 위, 음수가 아래를 뜻해요. 중력은 물체를 아래로 끌어당기니까 -9.81처럼 음수로 넣어요.

게임 중력과 시뮬레이션 중력의 차이

게임 속 더블 점프나 에어 컨트롤은 재미를 위해 현실의 물리 법칙을 일부러 깨뜨린 결과예요. Isaac Sim의 PhysX는 그렇지 않아요. 뉴턴의 운동 법칙을 그대로 따르려고 해요. 공중에 있는 동안엔 추가 가속을 줄 수 없고, 가속도는 오로지 작용하는 힘과 질량(F = ma)으로 결정돼요.

시뮬레이션 환경에서 중요한 건 재미가 아니라 효율성과 안전함이에요. 현실보다 빠르게 학습시키고, 현실에서는 엄두도 못 낼 실험까지 마음껏 해볼 수 있거든요. 같은 입력엔 늘 같은 결과가 나와야 여기서 똑똑해진 로봇을 현실로 안전하게 옮길 수 있어요. PhysX가 게임처럼 물리 법칙을 꾸미지 않는 이유도 이거예요.

질량이 영향을 주지 않는 이유

무거운 물체는 지구가 더 세게 잡아당겨요. 100kg 상자는 1kg 상자보다 100배 센 힘으로 당겨지죠.그런데 무거운 물체는 움직이기도 그만큼 어려워요. 100kg 상자를 1kg 상자와 같은 빠르기로 움직이려면 힘도 100배가 들거든요. 당기는 힘이 100배인데 드는 힘도 100배라서, 두 배수가 서로 지워져요. 그래서 진공에서는 1kg 상자와 100kg 상자가 나란히 떨어져요.

시뮬레이션의 진짜 강점은 여기예요. 진공, 무중력, 반중력처럼 현실에선 못 만드는 환경을 마음껏 시험할 수 있죠. 로봇을 화성에 보내기 전에, 화성 중력에서 미리 걷게 해볼 수도 있어요.

자주 마주치는 문제

실습 중 가장 많이 마주치는 네 가지예요. 클릭하면 원인과 해결법이 펼쳐져요.

중력 가속도 값을 바꿔도 변화가 없어요 ›
원인: world.reset() 뒤에 set_gravity()를 호출했을 가능성이 커요.
해결: 순서를 바꿔 set_gravity()를 먼저, world.reset()을 그 뒤에 호출해주세요.
상자가 바닥을 뚫고 들어가요 ›
원인: 중력 가속도가 너무 커서 한 프레임에 물체가 지나치게 멀리 이동한 경우예요. -274.0 같은 극단값일 때 자주 발생해요.
해결: 중력 가속도 값을 정상 범위로 되돌려주세요.
코드를 고쳐 실행해도 화면이 그대로예요 ›
원인: 서버가 잠깐 랙이 걸려 코드가 반영되지 않았을 수 있어요.
해결: Script Editor를 닫고 다시 접속한 뒤 코드를 실행해보세요.
화면이 멈추거나 갑자기 튕겨요 ›
원인: 같은 코드를 여러 번 실행하면 시뮬레이터 내부 상태가 쌓여 꼬일 수 있어요.
해결: 화면 왼쪽 위 File 메뉴 → Exit를 눌러 Isaac Sim을 완전히 종료한 뒤, 다시 접속해 코드를 실행하면 쌓인 상태가 깨끗이 정리돼요.

🥚
기본 · 1초 뒤 떨어지는 속도
상자를 10m에서 떨어뜨려 1초 뒤 속도가 얼마나 빨라졌는지 재요
import omni.usd
import omni.kit.app
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.api.objects import DynamicCuboid

if World.instance() is not None:
    World.instance().clear_instance()
omni.usd.get_context().new_stage()
world = World(stage_units_in_meters=1.0)
world.scene.add_default_ground_plane()

box = world.scene.add(DynamicCuboid(
    prim_path="/World/FallBox",
    position=np.array([0, 0, 10.0]),
    scale=np.array([0.3, 0.3, 0.3]), mass=1.0))
import asyncio
async def run():
    await world.reset_async()
    v_before = box.get_linear_velocity()[2]
    for _ in range(60):
        world.step(render=False)
    v_after = box.get_linear_velocity()[2]
    print(f"1초 동안 늘어난 속도 = {abs(v_after - v_before):.1f} m/s")

asyncio.ensure_future(run())
먼저 예측해봐요. 중력은 높이가 아니라 속도를 바꿔요. 10m에서 떨어지는 상자의 속도는 1초(60스텝) 동안 몇 m/s 늘어날까요?
내 답m/s
정답 → 약 9.8 m/s. 떨어지기 시작한 지점이 어디든, 중력 가속도는 1초마다 속도를 그만큼 키워요.
1get_linear_velocity()는 [x, y, z] 세 방향 속도를 돌려줘요. 위아래는 몇 번째 칸일까요.
2중력 가속도의 단위는 m/s²예요. 「1초에 속도가 얼마나 변한다」는 뜻인지 단위를 풀어 읽어봐요.
3재기 전과 후를 모두 읽어 뺀 이유가 있어요. 시작 속도가 얼마였든 늘어난 양은 같아요.
🐣
보통 · 달에서 1초 뒤
달 중력(-1.62)에서 2m 상자를 1초 떨어뜨린 직후 높이를 재요

내 답m

import omni.usd
import omni.kit.app
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.api.objects import DynamicCuboid

if World.instance() is not None:
    World.instance().clear_instance()
omni.usd.get_context().new_stage()
world = World(stage_units_in_meters=1.0)
world.scene.add_default_ground_plane()

box = world.scene.add(DynamicCuboid(
    prim_path="/World/FadeBox",
    position=np.array([0, 0, 30.0]),
    scale=np.array([0.3, 0.3, 0.3]), mass=1.0))
import asyncio
async def run():
    await world.reset_async()
    for i in range(90):
        g = -9.81 * (1.0 - i / 90)
        world.get_physics_context().set_gravity(g)
        world.step(render=False)
    z = box.get_world_pose()[0][2]
    print(f"중력을 0으로 줄이며 1.5초 뒤 높이 z = {z:.1f} m")

asyncio.ensure_future(run())
중력을 -9.81에서 0까지 서서히 줄이며 1.5초(90스텝) 떨어뜨려요. 최종 높이 z(m)를 입력해보세요.
내 답m
정답 → 약 22 m. 중력이 점점 약해져, 줄곧 -9.81로 떨어질 때보다 덜 내려와요.
1for 루프로 매 step마다 중력을 0에 가깝게 줄여요. set_gravity는 부르는 즉시 반영돼요.
2중력이 약해질수록 떨어지는 속도가 덜 빨라져요. 줄곧 -9.81일 때보다 더 떨어질까요, 덜 떨어질까요?

3강 한눈에 정리

  • PhysX가 중력, 충돌, 관성과 마찰을 쉼 없이 계산해서 물체가 현실을 재현한 것처럼 움직여요
  • 중력은 PhysicsContext가 담당해요. world.get_physics_context().set_gravity(g)로 바꿔요
  • Isaac Sim의 Z축은 양수가 위, 음수가 아래라 지구 중력 가속도는 -9.81 m/s²로 설정해요
  • 진공에서는 질량과 무관하게 1kg과 100kg 상자가 동시에 닿아요. 이게 갈릴레이의 가설이에요
  • 행성마다 중력 가속도가 달라요. 달은 -1.62, 화성은 -3.71, 목성은 -24.79 m/s²이고, 중력을 끄면 0이에요
