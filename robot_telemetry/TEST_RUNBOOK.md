# Isaac Sim 로봇 단계별 테스트 시나리오

이 문서는 서버에서 로봇을 실행하는 사람이 따르는 **실행 순서표**입니다.
목표는 빨리 어려운 지형으로 가는 것이 아니라, 문제가 생겼을 때 로그만으로 원인을
구분할 수 있도록 `서기 → 직진 → 회전 → 회전 후 이동 → 언덕 오르기 → 언덕 내려오기`
순서로 검증하는 것입니다.

## 0. 매 실행 전 공통 준비

- [ ] 이번 실행에서 사용할 로봇 모델(Go2/H1), 정책 파일명, 맵 이름을 기록했다.
- [ ] `motion_plan.json`을 복사하여 이번 실행에 사용한 버전을 보관했다.
- [ ] 이전 실행에서 바꾸지 않은 보상/정책/맵을 확인했다.
- [ ] 바꾼 값은 **한 번에 1~2개 이하**이며, 무엇을 왜 바꿨는지 기록했다.
- [ ] 새 `run_id`와 새 `.jsonl` 파일 경로를 만들었다. 기존 로그에 이어 쓰지 않는다.
- [ ] `run_started`에 `policy_path`, 로봇 모델, 맵, Isaac 버전, 보상 설정을 기록한다.
- [ ] 물리/제어 루프에서 설정한 `sample_period_s`마다 `sample`을 남긴다.

### 실행 메모 양식

```text
실행 일시:
run_id:
로봇 / 정책 파일:
맵 / 지형:
기준 실행 run_id: (없으면 최초 실행)
이번에 바꾼 값: 예) track_lin_vel_xy_exp 1.0 → 1.2
바꾼 이유/예상: 예) 직진 목표까지 더 잘 도달할 것으로 예상
```

## 1. 로그 기록 순서 (모든 단계 동일)

1. `phase_started`: 단계 이름, trial 번호, 목표, 통과 기준, **예상 결과**를 기록한다.
2. 제어 루프: 현재 실제 상태를 `sample`로 기록한다.
3. 낙상·충돌·시간 초과가 나면 리셋하기 **직전**에 `incident`를 기록한다.
4. 리셋하기 전 `evaluate_phase(...)`로 샘플과 사고를 평가한다.
5. `phase_completed`: 예상, 실제 결과, 통과 여부, 실패 이유, 측정값을 기록한다.
6. 단계가 통과했을 때만 다음 단계로 이동한다.

> 절대 원칙: 로봇을 리셋한 뒤의 값으로 낙상을 기록하지 않습니다. 넘어지기 직전/직후의
> 실제 상태가 있어야 나중에 원인을 분석할 수 있습니다.

## 2. 시나리오 목록

`motion_plan.json`의 숫자가 최종 기준입니다. 아래 표의 좌표는 기본 예시입니다.

| ID | 단계 | 난이도 | 시작 조건 | 목표 | 통과 기준 | 실패하면 우선 볼 로그 |
|---|---|---:|---|---|---|---|
| S01 | `stand` | 1 | 평지, 정지 명령 | 15초간 제자리 | 낙상 없음, 기울기/높이 안전 범위 | 높이, roll/pitch, 접지 수 |
| S02 | `forward` | 2 | S01 통과 | 평지 `(2,0,0)` | 목표 거리 허용치 이내 | 거리 변화, 명령 속도, 실제 속도 |
| S03 | `turn` | 3 | S01 통과 | 제자리 `yaw=90°` | 방향 오차 허용치 이내 | heading error, yaw rate, 기울기 |
| S04 | `turn_and_move` | 4 | S02·S03 통과 | `(2,2,0)`, `yaw=90°` | 거리·방향 모두 통과 | 회전 뒤 거리 감소 여부 |
| S05 | `hill_up` | 5 | S04 통과 | 경사 상단 `(4,0,0.6)` | 거리 통과, 상승 높이 통과, 낙상 없음 | 고도 증가, pitch, 접지 수 |
| S06 | `hill_down` | 6 | S05 통과 | 경사 하단 `(0,0,0)` | 목표 도달, 낙상 없음 | 속도, pitch, 충돌/낙상 |

각 시나리오는 `promotion_trials`만큼 반복합니다. 기본값은 3회입니다. 예를 들어
`S02 forward` 3회 중 한 번이라도 실패하면 S03로 진행하지 않고 S02 원인을 먼저 고칩니다.

## 3. 시나리오별 실제 실행 절차

### S01 — 서기

**목적:** 걷기 이전에 로봇의 초기 자세, 관절 명령, 접지, 물리가 정상인지 확인합니다.

1. 평지에서 로봇을 초기 자세로 리셋한다.
2. 전진 속도와 회전 속도 명령을 모두 `0`으로 둔다.
3. `stand`를 시작하고 15초 동안 관찰한다.
4. 이 기간에 최소 10개의 `sample`이 남았는지 확인한다.
5. 넘어짐, 몸통 높이 하락, 큰 기울기, 접지 수 급감이 있으면 `incident`를 즉시 기록한다.

**통과:** 낙상 0회, `base_height_m`가 최소 높이보다 크고, `max(|roll|, |pitch|)`가 최대 기울기보다 작음.

**대표 실패 해석**

| 로그 신호 | 1차 추정 |
|---|---|
| 시작 직후 높이가 낮음 | 초기 자세·관절 기본값·자산 충돌 설정 문제 가능성 |
| 명령이 0인데 기울기가 계속 증가 | 균형 정책 또는 물리/접지 문제 가능성 |
| 접지 수가 급감한 뒤 낙상 | 발 접촉·마찰·관절 제어 문제 가능성 |

### S02 — 평지 직진

**목적:** 명령을 실제 이동으로 바꾸는지 확인합니다.

1. S01 통과 정책으로 시작한다.
2. 목표를 `(2, 0, 0)`으로 설정하고 낮은 전진 명령을 준다.
3. 매 샘플에서 `target.distance_m`가 줄어드는지 확인한다.
4. 제한시간 전 목표 허용거리 안에 들어가면 종료한다.

**통과:** 낙상 없이 `end_distance_m <= max_distance_m`.

**대표 실패 해석**

| 로그 신호 | 1차 추정 |
|---|---|
| 명령 속도는 있는데 실제 `linear_mps`가 거의 0 | 정책이 걷기를 못 배웠거나 명령 축/단위 불일치 가능성 |
| 실제 속도는 있으나 목표 거리가 안 줄어듦 | 좌표계·heading·목표 계산 오류 가능성 |
| 거리 감소 중 tilt 증가 후 낙상 | 속도 대비 안정성 보상/정책 문제 가능성 |

### S03 — 제자리 회전

**목적:** 직진과 별개로 방향 제어를 확인합니다.

1. 선속도 명령은 0으로 둔다.
2. 목표 yaw를 `90°`로 설정한다.
3. `target.heading_error_deg`가 지속적으로 작아지는지 확인한다.

**통과:** 낙상 없이 최종 방향 오차가 설정값 이내.

**대표 실패 해석**

| 로그 신호 | 1차 추정 |
|---|---|
| yaw rate 명령은 있으나 yaw가 안 변함 | 회전 명령 연결 또는 정책 회전 학습 문제 가능성 |
| yaw가 목표를 반복해서 넘김 | 회전 명령이 과하거나 감쇠가 부족한 문제 가능성 |
| 회전 중 큰 roll/pitch | 회전 안정성 부족 가능성 |

### S04 — 회전 후 이동

**목적:** S02·S03을 합친 실제 미션 기초 능력을 확인합니다.

1. 목표를 `(2, 2, 0)`과 `yaw=90°`로 설정한다.
2. 회전 구간과 이동 구간을 로그의 `extra.stage`에 `turn`/`move`로 기록한다.
3. 회전이 끝난 뒤에만 전진 명령을 준다.

**통과:** 거리와 방향 기준을 모두 만족하고 낙상이 없음.

### S05 — 언덕 오르기

**목적:** 어려운 지형에서 앞발 접지, 몸통 기울기, 추진력을 검증합니다.

1. S04를 반복 통과한 정책만 사용한다.
2. 경사로 시작점과 상단 목표 `(4,0,0.6)`를 정확히 기록한다.
3. 샘플의 `extra.terrain`을 `hill`로 기록한다.
4. `pose.position_m[2]`가 시작보다 얼마나 증가하는지 기록한다.
5. 경사로 진입, 중간, 정상에 도달할 때 `extra.hill_section`을 남긴다.

**통과:** 목표 거리 만족, `altitude_gain_m >= min_altitude_gain_m`, 낙상 없음.

**대표 실패 해석**

| 로그 신호 | 1차 추정 |
|---|---|
| 목표 거리는 줄지만 높이 증가가 없음 | 경사로가 아닌 우회 경로이거나 z축/목표 계산 오류 가능성 |
| 높이는 증가하다 중간에서 멈춤 | 추진력·보폭·경사 학습 부족 가능성 |
| pitch가 한계 직전까지 증가 후 낙상 | 경사 자세 안정성 또는 발 접지 부족 가능성 |
| 접지 수가 불규칙하게 변하며 미끄러짐 | 마찰·발 접촉·지형 인식 문제 가능성 |

### S06 — 언덕 내려오기

**목적:** 중력 방향의 과속과 전복을 검사합니다.

1. 언덕 상단에서 시작한다.
2. 하단 목표를 지정한다.
3. 실제 전진 속도와 pitch를 상승 구간보다 촘촘히 기록한다.

**통과:** 목표 도달, 낙상·충돌 없음, 최대 기울기 제한 이내.

## 4. 실행 후 2분 점검표

- [ ] `.jsonl`에 `run_started`와 `run_completed`가 각각 1개 있다.
- [ ] 실행한 각 phase마다 `phase_started`와 `phase_completed`가 짝을 이룬다.
- [ ] 각 phase의 샘플이 10개 이상이다.
- [ ] 낙상/충돌/시간초과가 있었다면 대응하는 `incident`가 있다.
- [ ] `phase_completed`에 `predicted`, `actual`, `passed`, `reason`, `metrics`가 모두 있다.
- [ ] `export_artifacts(...)`를 실행해 `samples.csv`, `phase_summary.csv`, `phase_summary.md`를 생성했다.
- [ ] 이번 정책 파일과 `motion_plan.json` 사본을 로그와 같은 폴더에 보관했다.

## 5. 전달 패키지

분석을 의뢰할 때 다음을 하나의 압축파일 또는 같은 폴더로 전달합니다.

```text
run_YYYYMMDD_HHMM.jsonl        # 필수, 편집하지 않은 원본
motion_plan.json               # 필수, 그 실행에 실제 사용한 설정
phase_summary.csv              # 권장
samples.csv                    # 권장
run_note.txt                   # 권장, 실행 메모 양식 작성
report.html / 영상             # 있으면 매우 유용
```

분석 요청에는 “정상이라고 기대한 동작”, “실제로 관찰한 현상”, “이번에 바꾼 값”을 한 줄씩
적습니다. 이 정보와 원본 로그를 합치면 설정, 정책, 좌표계, 지형, 안전성 중 어느 층을 먼저
의심해야 하는지 분리해 진단할 수 있습니다.
