# H1 기술 개선 리포트·실험 로그 지침

## 1. 목적과 제출 기준

이 지침은 예선 H1 정책의 실험 기록을 기술 개선 리포트로 바꾸기 위한 기준이다.

예선 제출물은 다음 세 가지다.

1. `exported/policy.pt`: `play.py` 실행으로 생성되는 제출 정책
2. `exported/env.yaml`: 실제 학습 환경과 reward 설정
3. 기술 개선 리포트: 무엇을 왜 바꿨고 어떤 결과가 나왔는지 설명

리포트의 설명, `env.yaml`의 실제 reward 값, 평가 영상에서 관찰한 행동은 서로 일치해야 한다.
`model_best.pt`는 학습 체크포인트이며 제출 정책은 아니다.

## 2. 파일과 이름 규칙

실험 하나는 `RUN_ID` 하나로 관리한다. 날짜와 순번은 실행일 기준이다.

```text
reports/
  train_YYMMDD-NN.log             # 학습 터미널 원문
  train_YYMMDD-NN_config.json     # 실행 전 설정·예상·변경값
  train_YYMMDD-NN_add.md          # 실행 후 분석·판정
  eval_YYMMDD-NN.log              # 평가(play) 터미널 원문
  eval_YYMMDD-NN_metrics.csv      # 평가 수치 표
  eval_YYMMDD-NN_add.md           # 영상 관찰과 분석
  experiment_history.csv          # 모든 실험의 비교용 누적 표
```

- 코드나 reward를 바꾼 실험은 새 번호를 쓴다.
- 설정을 바꾸지 않은 재실행은 `*_rerun-01.log`처럼 원 실험에 연결한다.
- 원문 `.log`는 수정하지 않는다. 해석과 결론은 반드시 `*_add.md`에 기록한다.
- 변경 전후 비교는 명령, 지형, 시간, 난수 시드, iteration, 환경 수를 동일하게 유지한 경우만 가능하다.

## 3. 변경 원칙

1. 학생 수정 대상은 `training/humanoid/humanoid_rewards.py`의 reward 가중치뿐이다.
2. 한 실험에서는 **가설 하나와 reward 변수 하나**만 바꾼다.
3. 첫 실험은 기본 reward를 유지한 기준선(baseline)이다.
4. 수치를 바꾸기 전 예상 방향과 통과 기준을 먼저 기록한다.
5. 결과가 나쁘거나 애매해도 삭제하지 않고 실패 원인과 다음 결정을 남긴다.

## 4. 대회 시나리오와 측정값

| 시나리오 | 비중 | 필수 기록값 |
|---|---:|---|
| H1 제자리 균형 | 0.15 | 생존 시간, 생존률, 평균/최대 기울기 |
| H2 전진 속도 추종 | 0.20 | 목표 `vx`, 실제 `vx`, 선속도 오차, 생존률 |
| H3 좌우 속도 추종 | 0.10 | 목표 `vy`, 실제 `vy`, 좌우 속도 오차, 생존률 |
| H4 회전 복합 추종 | 0.10 | 목표 `wz`, 실제 `wz`, 각속도 오차, 생존률 |
| H5 약한 요철 | 0.15 | 지형 레벨, 생존률, 추종 오차, 최대 기울기 |
| H6 경사 ±10° | 0.15 | 경사각, 상승/하강, 생존률, 추종 오차 |
| H7 밀침 회복 | 0.15 | 힘의 크기·방향·시점, 회복 시간, 넘어짐 여부 |

시나리오 점수는 `생존률 × 추종 점수`이다. 따라서 빠르지만 자주 넘어지는 정책보다, 전체 H1~H7에서 안정적으로 생존하면서 명령을 잘 추종하는 정책을 목표로 한다.

## 5. reward 변경의 근거 작성

| reward 변수 | 주로 개선하려는 항목 | 예상 부작용 |
|---|---|---|
| `track_lin_vel_xy_exp` | H2, H3, H5, H6 속도 추종 | 자세 안정성보다 속도를 우선할 수 있음 |
| `track_ang_vel_z_exp` | H4 회전 추종 | 회전 중 몸통 흔들림 증가 가능 |
| `feet_air_time` | H2, H3, H5, H6 보행 리듬 | 과도하면 큰 보폭·불안정 가능 |
| `termination_penalty` | H1~H7 넘어짐 억제 | 과도하면 소극적으로 움직일 수 있음 |
| `flat_orientation_l2` | H1, H5, H6, H7 자세 안정 | 과도하면 경사 적응·빠른 보행 저하 가능 |
| `ang_vel_xy_l2` | H1, H5, H6, H7 흔들림 억제 | 충격 회복 반응이 둔해질 수 있음 |
| `action_rate_l2` | 동작 부드러움·안정성 | 급격한 회복 동작이 느려질 수 있음 |

## 6. PASS 판정 규칙

- **PASS**: 미리 정한 예상 방향과 통과 기준을 만족하고, 핵심 부작용이 없다.
- **PARTIAL**: 예상 방향은 맞지만 목표 수치에 못 미치거나 부작용이 있다.
- **FAIL**: 핵심 수치가 반대 방향으로 악화되거나 넘어짐이 늘었다.
- **INCONCLUSIVE**: 비교 조건이 달라 원인 판단을 할 수 없다. 동일 조건으로 재시험한다.

## 7. 최종 제출 전 확인

- [ ] 최종 `policy.pt`가 실제로 존재한다.
- [ ] 최종 `env.yaml`이 존재하며 리포트에 적은 reward 값과 일치한다.
- [ ] 최종 `policy.pt`는 최종 평가 영상에서 확인한 정책이다.
- [ ] H1~H7 평가 결과와 최종 선정 이유가 리포트에 있다.
- [ ] `policy.pt`, `env.yaml`, 기술 개선 리포트를 팀 대시보드에 제출한다.

본선 활용성도 한 문단으로 기록한다. 최종 정책은 경로 계획기가 주는 `vx`, `vy`, `wz` 명령을 수행하는 역할이므로, 전진·좌우·회전과 지형 안정성을 함께 검증해야 한다.
