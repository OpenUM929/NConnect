## 3. 학습 지표와의 정합성

영상 관찰은 학습 지표와 서로 어긋나지 않는다.

- [사실] Run 03의 마지막 `Metrics/base_velocity/error_vel_yaw = 1.7672`이다.
- [사실] `h1_task/env_cfg.py:120`에서 `ang_vel_z` 명령 범위는 `(-1.0, 1.0)` rad/s다.
- [추론] yaw 오차의 크기가 명령의 최대 절댓값(1.0)보다 크므로, 관찰된 좌회전은 **명령받은 선회가 아니라 명령과 무관한 회전**일 가능성이 높다. 명령을 전혀 따르지 않고 정지해 있기만 해도 오차는 최대 1.0을 넘지 않기 때문이다.
- [사실] `Episode_Termination/time_out = 0.7215`, `base_contact = 0.2785`로, 낙상 없이 시간 종료되는 비율이 높다. 영상의 "낙상 없음"과 일치한다.
- [추론] 낙상 회피와 제자리 유지가 동시에 나타나므로, 정책이 명령 추종보다 생존을 우선하는 소극적 전략에 머물러 있을 가능성이 있다.

`train_260828-03_add.md` §6.3은 다음을 사전에 규정했다.

> "Run 03은 Run 02 대비 낙상 지표가 개선돼도 두 추종 오차가 모두 더 악화되거나 영상에서 회전 실패가 확인되면 채택하지 않는다."

1. `error_vel_xy` 0.3596 → 0.4182 (+16.30%), `error_vel_yaw` 0.9341 → 1.7672 (+89.19%) — 두 추종 오차가 모두 악화
2. 영상에서 명령과 무관한 지속 좌회전 확인 — 회전 실패

낙상 지표가 0.2979 → 0.2785로 소폭 개선됐으나, 사전 등록 기준상 채택 조건이 아니다.

## 6. 절차 위반 기록 — 실행 게이트 미준수

`train_260828-03_add.md` §6.4는 다음을 실행 조건으로 사전 등록했다.

> "Run 03 값 `-90`은 사전 등록 후보이나, 아직 실행 승인값은 아니다. Run 02의 동일 조건 1,000-step play 평가로 실제 보행·회전 행동을 먼저 확인한다. 그 평가에서 yaw 위험이 실제로 확인되면, 더 큰 종료 벌점 대신 추종 보상 또는 별도의 보상 항을 다루는 새 가설을 테스트 기획자가 설계해야 한다."

**이 게이트는 지켜지지 않았다.** Run 02 play 평가(`eval_260828-02_add.md`에서 미완료로 기록됨)를 수행하지 않은 채 Run 03이 실행됐다.

게이트를 지켰다면 Run 02 영상에서 yaw 위험이 확인됐을 것이고, §6.4의 분기 지시대로 "더 큰 종료 벌점" 대신 "추종 보상"을 다루는 가설로 넘어갔을 것이다. 이는 Run 03 실패 후 Run 04에서 실제로 채택한 경로와 같다. 즉 **사전 계획은 옳은 분기를 이미 담고 있었고, 손실된 것은 계획의 품질이 아니라 40분의 학습 시간이다.**

재발 방지: 사전 등록 문서에 실행 게이트가 있으면, 게이트 항목의 증거를 확보하기 전에는 다음 학습을 시작하지 않는다.

## 7. 평가 완료에 필요한 증거

현재 영상 관찰은 1회 rollout의 정성 관찰이다. 판정을 보강하려면 다음이 필요하다.

- 두 play 실행의 원문 로그와 `--video_length`, `--num_envs` 값
- 사용자가 관찰한 영상 파일의 특정
- 관찰 항목의 정량화: 생존 시간(step), 회전 방향과 대략적 각속도, 명령 대비 실제 이동 여부
- Run 02 checkpoint(`model_best_20260828094844.pt`)의 동일 조건 play — Run 03과의 영상 대조군이 아직 없다

⚠️ Run 02 영상 대조군이 없으므로, 관찰된 제자리 좌회전이 `-90`에서 새로 생긴 것인지 `-50`에서도 이미 있었는지 구분할 수 없다. `error_vel_yaw`가 Run 02에서도 0.9341로 이미 높았던 점을 고려하면 **후자일 가능성이 있다.** Run 04 결과 판정 시 이 대조군 부재를 감안해야 한다.
