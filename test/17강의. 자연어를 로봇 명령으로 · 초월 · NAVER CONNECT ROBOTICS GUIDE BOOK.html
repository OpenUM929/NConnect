17. 자연어를 로봇 명령으로

잘 걷게 된 로봇에게, 이번엔 "생각하는 힘"을 달아줄 차례예요.로봇의 대뇌가 될 LLM을 처음으로 호출해서 판단을 맡겨봅니다. 그 판단이 속도 벡터로 돌아오는, 첫 번째 연결을 만들어보는 거예요.

①

생각 열기

잘 걷는 로봇의 다음 과제

우리가 3 챕터까지 만들고 학습시킨 로봇은 [1.0, 0.0, 0.0] 처럼 숫자들로 구성된 명령은 정확히 알아듣고 그대로 움직여요. 하지만 "앞에 있는 책상까지 걸어가"처럼 사람이 평소에 쓰는 문장은 전혀 알아듣지 못해요.로봇이 알아듣는 말과 사람이 쓰는 말이 서로 다르기 때문이에요.· 제어 명령(속도 벡터)은 로봇 정책(Policy)이 알아듣는 수치 데이터 [vx, vy, yaw]예요· 자연어는 사람이 대화할 때 쓰는 말이에요아래에서 버튼을 누르며, 사람의 말 한마디가 로봇에게 닿기까지 무슨 일이 필요한지 직접 따라가보세요.

사람의 심부름 한 마디, 로봇의 단계별 생각
"목말라, 주방에서 물 한 잔만 가져다줄래?"
로봇이 거실에 서 있어요. 이 명령을 잘 알아들을까요?
정책 입력 칸 velocity_command = [ ?, ?, ? ] 문장은 들어가지 않아요
방금 본 것처럼, 사람의 말 한마디가 로봇의 걸음이 되려면 여러 단계의 생각을 거쳐 숫자 세 개로 구성된 속도 벡터 명령어로 바꿔야 해요. 로봇은 그 명령어대로 걷는 건 잘하지만, 사람의 자연어를 알아듣고 "무엇을 할지" 정하는 일은 아직 못 해요. 오늘은 그 일을 대신해줄 LLM을 데려와 처음 연결해요.

③

개념 만나기

여러분은 이미 LLM을 쓰고 있어요

ChatGPT, Gemini, Claude 등 궁금한 걸 물어보면 척척 답해주는 그 AI들이 바로 LLM(대규모 언어 모델)이에요. 지금까지 우리는 LLM을 사람과 1:1로 대화하는 상대로만 써왔죠.그런데 LLM의 재능은 수다만이 아니에요. 사람의 언어를 이해하고, 판단하고, 계획을 세우는 능력이 있거든요. 오늘은 이 능력을 빌려와요. 지금까지는 사람이 그 판단을 제어 명령으로 일일이 입력하여 로봇에게 시켰어요. 오늘은 그 사람과 로봇 사이에 LLM을 세우는 거예요.

지금까지 · 사람과 로봇 제어 명령으로 시켰어요
사람 → 제어 명령속도 벡터 → 로봇
로봇 정책은 제어 명령만 알아들어서, 사람이 판단을 일일이 그 형태로 입력해줘야 했어요.
오늘부터 LLM이 로봇의 대뇌가 돼요
사람자연어 명령 → LLM판단·계획 → 로봇행동
LLM이 사람의 언어를 이해하고, 판단하고, 로봇 정책이 아는 제어 명령(속도 벡터)으로 바꿔줘요.
그래서 LLM이 오늘 맡는 일은 세 가지예요
  1. ①말 알아듣기

    사람의 자연어를 이해해요

  2. ②판단·계획

    무엇을, 어떤 순서로 할지 정해요

  3. ③제어 명령으로 변환

    판단을 속도 벡터 [vx, vy, yaw]로 바꿔줘요

숫자 세 개가 뜻하는 것

방금 ③번에 나온 속도 벡터 [vx, vy, yaw]는 "어느 방향으로 얼마나 빠르게"를 담은 숫자 세 개예요.읽는 법은 간단해요. 숫자의 크기는 속도, 부호는 방향이에요. 0이면 그 방향으로는 움직이지 않아요.방향의 기준은 2챕터에서 배운 Z-up 좌표축이에요. 로봇의 정면이 +x, 왼쪽이 +y, 위가 +z죠. yaw는 그 z축을 중심으로 도는 속도라서 양수가 반시계(왼쪽)예요.아래에서 세 값을 직접 움직여, 축과 로봇이 어떻게 따라 움직이는지 확인해보세요.

vx 앞뒤로 가는 속도 (m/s) 뒤로 앞으로 +0.4
vy 옆으로 가는 속도 (m/s) 오른쪽으로 왼쪽으로 0.0
yaw 제자리에서 도는 속도 (rad/s) 오른쪽으로 돌기 왼쪽으로 돌기 +0.3
velocity_command = [0.4, 0.0, 0.3]

앞으로 0.4m/s, 왼쪽(반시계)으로 0.3rad/s 돌기 — 로봇 몸 기준이라, 돌아 있으면 앞도 함께 돌아가요.

이렇게도 해보세요
그래서 [0.4, 0.0, 0.3]은 "앞으로 0.4m/s로 가면서, 왼쪽으로 0.3rad/s로 돈다"는 뜻이에요.옆으로 가는 값이 0이니 게걸음은 치지 않고, 앞으로 걸으면서 몸을 왼쪽으로 트는 움직임이 되죠.

우리 몸의 설계도, 대뇌와 소뇌

그런데 LLM이 판단을 대신해준다고 해서, 걷기까지 LLM이 하는 건 아니에요. 판단과 걷기는 서로 다른 능력이라 나눠 맡죠.사람의 뇌가 이미 그렇게 하고 있어요.자전거를 타면서 친구와 수다를 떨어본 적 있나요? 페달을 어떤 힘으로 밟을지, 핸들을 몇 도 틀지 일일이 생각하지 않죠.균형은 소뇌가 알아서 잡아주고, 그동안 대뇌는 "어느 길로 갈까", "저 모퉁이 조심하자" 같은 판단을 해요.걷는 능력과 판단하는 능력이 분업돼 있는 거예요. 로봇도 똑같이 설계하면 돼요.

LLM이 대뇌 역할을 하게 된 이유

그런데 왜 하필 LLM일까요?사실 로봇의 "대뇌 자리"는 오랫동안 비어 있었어요. 그 자리에 LLM이 앉기까지의 이야기를 세 장면으로 넘겨봐요.

옛 숙제

옛날엔 이 자리를 채울 수 없었어요

대뇌가 하는 판단엔 상식이 필요해요. 물컵은 주방에 있다는 것, 의자는 밀면 움직여도 벽은 움직이지 않는다는 것, 뜨거운 컵은 조심해야 한다는 것. 이런 걸 일일이 코드로 적는 건 불가능했어요. 그래서 오랫동안 이 대뇌 자리는 비어 있었죠.

전환점

LLM은 상식을 통째로 품었어요

사람이 쓴 방대한 글로 학습한 LLM은 언어를 이해하고, 상식을 갖추고, 추론까지 할 수 있어요. "복도에 물청소 중인 구역이 있다"고만 알려줘도, 미끄러우니 돌아가자는 판단은 따로 가르치지 않았는데도 스스로 내려요.

지금

그래서 로보틱스는 이렇게 움직여요

위에는 자연어를 이해하는 큰 모델(대뇌), 아래에는 몸을 다루는 빠른 정책(소뇌). 요즘 세계의 휴머노이드 로봇들이 바로 이 길을 걷고 있어요.

④

직접 해보기

연결을 확인하고, 판단을 맡기고, 속도 벡터로 받아와요. 이 세 걸음으로 가요.

첫 걸음 · 코드로 LLM과 대화하기

이제 코드로 LLM과 직접 연결해 대화를 나눠봐요. 로봇은 잠깐 두고, 우리가 보낸 질문에 LLM이 답하는지부터 확인하는 거예요.

▶ 참고 LLM을 로컬에서 쓰는 이유
방금 호출한 LLM은 실습 PC 안에 통째로 들어 있어요. 올라마(Ollama)라는 무료 프로그램으로 isaac-tutor-ko-9b 모델이 돌아가거든요. 가입도, 결제도, 인터넷도 필요 없어요.이 모델은 네이버 커넥트재단이 이번 대회 참가자들을 위해 파인튜닝한 한국어 로봇 튜터 LLM이에요. 로봇 명령·판단 상황에 맞춰 다듬어져 있어서, 이 실습에 딱 맞게 답해줘요.다만 이 모델은 Isaac Sim 코딩을 가르치도록 특화돼 있어요. 그래서 무엇을 물어도 친절한 선생님처럼 코드 예시와 목록을 곁들여 길게 답하려는 습관이 있어요. 사람에겐 좋은 설명이지만, 우리는 판단 문장이나 숫자만 필요하죠.그래서 실습 코드의 질문 끝마다 "코드·목록·부가 설명은 쓰지 마"라고 못박아 두었어요. 필요한 형태로만 답을 받아내는 것, 다음 강에서 본격적으로 배울 프롬프트 설계의 첫걸음이에요.

두 번째 걸음 · 판단을 글로 맡기기

연결이 확인됐으니 로봇의 상황을 통째로 LLM에게 넘겨봐요. 도서관 정리 로봇의 상황을 글로 주면, LLM이 순서를 정하고 그 이유까지 알려줘요.

import requests, threading LLM_URL = "http://127.0.0.1:11434/api/chat"MODEL = "isaac-tutor-ko-9b" situation = """너는 도서관 정리 로봇의 판단을 도와주는 시스템이야. [지금 상황]- 로봇은 도서관 입구에 서 있다.- 정리할 책이 두 권 보인다. · 책 A: 가까운 책상 위 (3m 거리) · 책 B: 통로 한가운데 바닥 (7m) - 사람이 밟고 미끄러질 수 있다- 임무: 책을 모두 제자리에. 단, 사람에게 피해를 주면 안 된다. 어떤 순서로 움직이는 게 좋을까?판단과 이유만 글로 짧게 답해줘. 한 문장마다 줄을 바꾸고, 코드나 코드 블록은 절대 쓰지 마.""" def worker(): try: resp = requests.post(LLM_URL, json={ "model": MODEL, "messages": [{"role": "user", "content": situation}], "think": False, "stream": False, "options": {"temperature": 0.3}, }, timeout=60) answer = resp.json()["message"]["content"] answer = answer.split("```")[0].strip() print(answer) except Exception as e: print("호출 실패:", e) threading.Thread(target=worker, daemon=True).start()

책 B는 통로 한가운데 있어서 지금 이 순간에도 사람이 밟고 미끄러질 수 있습니다.
책 A는 책상 위에 있어 당장 위험하지 않습니다.
그래서 위험한 책 B(7m)를 먼저 옮기고, 돌아오는 길에 책 A(3m)를 옮기겠습니다.
LLM이 두 책의 거리와 위험을 스스로 저울질해, 어느 책을 먼저 옮길지 순서와 이유를 문장으로 돌려줘요.
판단과 문장은 실행할 때마다 달라질 수 있어요.
답에 어느 책을 먼저 할지 순서가 들어 있다
그 순서에 근거가 따라온다

세 번째 걸음 · 판단을 속도 벡터로 받기

같은 판단을 이번엔 속도 벡터 [vx, vy, yaw]로 받아요. 답에서 숫자 줄만 골라내면, 3 챕터의 정책이 그대로 받던 그 입력이 돼요.

import requests, threading LLM_URL = "http://127.0.0.1:11434/api/chat"MODEL = "isaac-tutor-ko-9b" situation = """너는 도서관 정리 로봇의 판단을 도와주는 시스템이야. [지금 상황]- 로봇은 입구에서 정면(+x)을 보고 서 있다.- 책 B가 정면에서 살짝 왼쪽, 7m 앞 바닥에 있다.- 임무: 책 B 쪽으로 천천히 이동 시작. 짧게 설명할 거면 한 문장마다 줄을 바꿔 적고,답의 맨 마지막 줄은 [전진 m/s, 좌우 m/s, 회전 rad/s] 숫자 세 개로만 끝내. 예: [0.4, 0.0, 0.3]대괄호 안에는 숫자만 적어라. 이름표나 단위(m/s 같은 것)를 넣지 마라.그 뒤에 아무 말도, 코드도, 요약도 덧붙이지 마.""" def three_numbers(line): nums = [] for chunk in line.replace("[", " ").replace("]", " ").replace(",", " ").split(): try: nums.append(float(chunk)) except ValueError: pass return nums if len(nums) == 3 else None def worker(): try: resp = requests.post(LLM_URL, json={ "model": MODEL, "messages": [{"role": "user", "content": situation}], "think": False, "stream": False, "options": {"temperature": 0.3}, }, timeout=60) except Exception as e: print("호출 실패:", e) return text = resp.json()["message"]["content"] print(text) velocity_command = None for line in reversed(text.strip().splitlines()): velocity_command = three_numbers(line) if velocity_command: break if velocity_command: print("velocity_command =", velocity_command) else: print("숫자 세 개를 못 찾았어요. LLM이 약속을 어긴 거죠. 18강에서 이걸 해결해요.") threading.Thread(target=worker, daemon=True).start()
// 표시된 줄을 클릭하면 해설
밑줄 친 줄을 클릭하면 무슨 일을 하는지 짚어줄게요.
책 B는 정면에서 살짝 왼쪽, 7m 앞 바닥에 있습니다.
천천히 전진하면서 왼쪽으로 조금씩 회전해 접근하겠습니다.
[0.4, 0.0, 0.3]
velocity_command = [0.4, 0.0, 0.3]
마지막 줄에 velocity_command = [0.4, 0.0, 0.3] 같은 속도 벡터가 출력돼요.
다만 LLM이 늘 이렇게 답해주진 않아요. 숫자를 빼먹거나 다른 말을 덧붙이면 숫자를 못 꺼내죠. 그래서 어떤 답이 와도 흔들리지 않게 만드는 법을 18강에서 배워요.
velocity_command = [0.4, 0.0, 0.3] 형태의 리스트가 출력된다
세 숫자가 각각 전진·좌우·회전 속도에 대응한다
실습 1의 답을 잠깐 음미해보세요. 우리는 "A를 먼저, B를 나중에" 같은 순서 규칙을 코드로 한 줄도 안 짰어요. 상황을 글로 줬을 뿐인데, LLM은 거리와 위험을 스스로 저울질해 이유가 붙은 순서를 만들어냈어요. 어느 책을 먼저라고 답하든, 그 나름의 근거가 따라와요. 이게 우리가 찾던 대뇌의 재능이에요.

reply = """장애물이 왼쪽에 있어 오른쪽으로 살짝 틀며 갈게요.
[0.6, 0.0, -0.4]"""

내 답
정답 → -0.4
1splitlines()[-1]로 마지막 줄만 잘라내요.
2strip("[] ")로 대괄호를 떼고, 쉼표로 나눠 float으로 바꿔요.

보통 · 숫자가 없으면 멈추기
LLM이 숫자를 빼먹고 말로만 답했어요. try/except로 안전하게 정지시켜봐요.
def parse_velocity(reply):
    try:
        last = reply.strip().splitlines()[-1]
        vx, vy, yaw = [float(n) for n in last.strip("[] ").split(",")]
        return (vx, vy, yaw)
    except (ValueError, IndexError):
        return (0.0, 0.0, 0.0)

reply = "음, 지금은 왼쪽으로 도는 게 좋을 것 같아요!"
vx, vy, yaw = parse_velocity(reply)
print(f"명령 → {vx} {vy} {yaw}")
숫자를 못 찾았을 때 나오는 vx 값을 입력해보세요.
내 답
정답 → 0.0 (셋 다 0, 제자리 정지)
1float(...)가 숫자 아닌 글자를 만나면 ValueError가 나요.
2그러면 except로 넘어가 (0, 0, 0)을 돌려줘요.
3멈춤(0)이 왜 안전한 기본값일지 생각해보세요.
🐥
도전 · JSON 답에서 값 꺼내기
이번엔 LLM이 JSON으로 답했어요. json.loads로 풀어 vy를 꺼내봐요.
import json

reply = '{"velocity_x": 0.5, "velocity_y": -0.2, "velocity_yaw": 0.8, "reason": "왼쪽 벽을 피해서"}'

cmd = json.loads(reply)
print(f"vx={cmd['velocity_x']}  vy={cmd['velocity_y']}  yaw={cmd['velocity_yaw']}")
출력된 vy(velocity_y) 값을 입력해보세요.
내 답
정답 → -0.2
1json.loads는 JSON 글자를 딕셔너리로 바꿔줘요.
2cmd["velocity_y"]처럼 키로 값을 꺼내요.

17강 한눈에 정리

  • 잘 걷는 것(How)과 무엇을 할지(What)는 다른 능력. 그래서 분업해요
  • 대뇌(LLM)는 판단·계획, 소뇌(.pt)는 균형·보행. 우리 몸과 같은 설계예요
  • LLM은 언어·상식·추론을 품고 있어 따로 안 가르친 상식까지 판단에 끌어와요
  • LLM의 약점은 빠른 반복이에요. 소뇌는 빠르고 대뇌는 느린데, 이 속도 차이는 19강에서 다뤄요
  • 자연어 → 판단 → [vx, vy, yaw]. 첫 연결이 오늘 성사됐어요
  • 다만 LLM이 늘 같은 형태로 답해주진 않아요. 그래서 답을 믿을 수 있게 만드는 일이 남았어요
다음 강 안내

오늘 연결은 성공했지만, LLM이 늘 같은 형태로 답해주진 않아요. 다음 강에서는 답을 반드시 정해진 형식(JSON)으로만 받도록 강제하고, 들어온 답을 검사해 틀리면 바로잡는 안전장치까지 더해서, 어떤 답이 와도 끄떡없게 만들어요.
