## 7. 재현 (저장소 루트, 표준 라이브러리, 읽기 전용)

```python
import csv, collections, statistics as st
B = "workspace/_keep/go2_a017_full_suite/evaluation/a017/cases"
def envs(p):
    by = collections.defaultdict(list)
    for r in csv.DictReader(open(p)): by[int(r["env_id"])].append(r)
    out = {}
    for e, rs in by.items():
        k = []
        for r in rs:
            if r["terminated"] == "1" or r["truncated"] == "1": break
            k.append(r)
        out[e] = k
    return out
def onset(rs):  # evaluator rule: 0.5 s grace, 0.5 s continuous not-upright
    run = 0
    for i, r in enumerate(rs):
        if i < 25: continue
        if r["upright"] == "0":
            run += 1
            if run >= 25: return i - 24
        elif r["upright"] == "1": run = 0
for cid in ("stairs_10_down", "stairs_15_down", "slope_plus_20"):
    for seed in ("101", "202", "303"):
        tr, rr = [], []
        for rs in envs(f"{B}/seed_{seed}/{cid}/steps.csv").values():
            j = onset(rs)
            if j is None or j + 100 >= len(rs): continue
            tr.append(float(rs[j+100]["terrain_z"]) - float(rs[50]["terrain_z"]))
            rr.append(float(rs[j+100]["root_z"]) - float(rs[50]["root_z"]))
        print(cid, seed, len(tr), f"terrain {st.median(tr):+.3f} root {st.median(rr):+.3f}")
# 기대: stairs_10_down 101 31 terrain +0.103 root -0.092 · slope_plus_20 101 7 terrain +0.216 root +0.075
```

## 9. 계단이 0인 이유

1. **점수 구조 [확인]:** G5 = 12개 case·seed 곱의 최솟값이다. 역피라미드(이름 "down", 실제 오르기) case가 생존 .00~.22·추종 .12~.18이라 곱이 0이다.
2. **행동 [확인]:**
   - 로봇이 4~5초에 첫 계단 앞에 도착한다.
   - 오르기를 몇 번 시도한다. Pilot env 0 telemetry에서는 3.5~7.5초에 속도가 붙었다가 몸이 잠깐 올라가고 다시 내려온다.
   - 결국 몸을 10~14cm 낮춘 채 멈추고 끝까지 움직이지 않는다. 기울기는 수평이다.
   - Pilot 계단 오르기 영상(seed 202, 32대 측정과는 다른 4대 재생)에서도 2.5초에 계단 앞에서 웅크리고, 앞발을 첫 단에 걸친 채 4~8초 정지한다 [VIDEO_OBSERVED, 정성].
3. **계측 [확인]:** 멈춘 뒤 기록 높이 감소의 절반은 스캐너 격자(1.6×1.0m)가 앞 계단을 평균에 넣은 편향이다. 정확히 재도 추종 .12~.16이라 G5는 1.27점을 넘지 못한다.
4. **원인에서 배제한 것:**
   - 기울어 넘어짐: 정지 뒤 기울어진 행 비율 0~0.11 [확인]
   - 도메인 랜덤화: 계단 case는 DR 없음 [확인]
   - `lin_vel_z_l2` 크기: 실제 오른 행 벌점 .023~.051/s vs 정지 손실 .68/s [확인, 선택 편향 주의]
5. **Isaac Lab·가이드에서 확인한 사실:**
   - `feet_air_time` 식은 `Σ(체공시간 − 0.5)·첫 접지`다. 체공 0.5초 미만 걸음마다 **음수**다. A017 학습 로그 항 −.027/s로 확인했다. 멈추면 이 항은 0이다.
   - 추종 커널상 멈춰도 최대 보상의 37%를 받고, 종료 벌점 항은 없다.
   - 가이드북 14강의 기준 예시(Default + `track` 1.5 + `lin_vel_z` −2)도 5000 iter에서 "계단 등을 올라가는 데 많이 어색"하다.
6. **관련 있는 것 [확인, 한 쌍]:** `track` 1.2→1.4에서 10cm 계단 2단 도달이 10~11→3~5로 줄었다(접근 속도 증가와 동반).
7. **남은 원인 후보 — 판별 불가 [모름]:**
   - 계단 턱에서 발이 걸리거나 발 들기가 부족하다.
   - 접근이 빠르다.
   - 학습 중 계단 노출이 부족하다(커리큘럼은 못 오르는 로봇을 쉬운 지형으로 강등한다, `terrain_levels_vel`).
   - 현재 telemetry는 몸통만 기록한다. 발 접촉·발 높이·관절 자료가 없어서 첫째 후보를 가를 수 없다.
