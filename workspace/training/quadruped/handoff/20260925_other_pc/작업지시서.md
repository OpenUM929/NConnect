# 다른 PC 검증 작업지시서 — 2026-09-25

## 0. 먼저 알아야 할 것: 이 일은 메모리 때문에 막힌 것이 아니다

검증은 **이 PC 에서 이미 끝났다.** 검사 한 건의 최대 메모리는 **152 MB** 이고,
이 기계는 7,971 MB 중 **6,000 MB 가 우리 작업과 무관하게** 차 있었다(svchost 1,043 ·
claude 444 · explorer 347 · msedge 438 · codex 192 · Taskmgr 162 MB).
중단은 기계의 기준선 때문이지 검사의 크기 때문이 아니다.

그러므로 다른 PC 의 쓸모는 **속도와 무중단**이다:
- 모듈을 통째로 돌릴 수 있다(여기서는 클래스·검사 단위로 쪼개야 했다)
- 중단 없이 전수를 한 번에 돌려 이 문서의 기대값과 대조할 수 있다

## 1. 준비

저장소 전체를 복사한다(`workspace/_keep` 의 수확물 포함 — 없으면 상당수 검사가 SKIP 된다).
Python 3.13, 추가 패키지 없음. 디스크 여유 **10 GB 이상**(검사 하나가 저장 팔을 600 MB 복사한다).

```
cd <저장소 루트>
python -m unittest tools.test_go2_defect_ledger_contract    # 10 OK 면 준비 완료
```

## 2. 도는 방법

`run_one.py` 는 검사 하나·클래스 하나를 **자기 프로세스에서** 돌리고 최대 메모리를 찍는다.
저장소 루트는 파일 위치에서 유도하므로 어느 PC 에서도 그대로 돈다.

```
python workspace/training/quadruped/handoff/20260925_other_pc/run_one.py <대상>
```

메모리가 넉넉하면 모듈 단위가 빠르다:

```
python -m unittest tools.<모듈>
```

느린 검사는 기본적으로 생략된다. **전수로 돌리려면 반드시** 켠다:

```
GO2_SLOW_TESTS=1 python -m unittest tools.test_go2_g_a044_package_contract
```
(Windows PowerShell: `$env:GO2_SLOW_TESTS=1` 먼저)

## 4. 이 PC 에서 하지 못한 것은 없다 — 대신 **새로 찾은 것**이 있다 (최우선)

**C-34 (중대, OPEN)** — 발행된 v8 팔 `G-A046` 의 사전등록이 기반 데이터와 어긋난다.

python -c "import sys,json,pathlib;sys.path.insert(0,'tools');sys.path.insert(0,'workspace/training/quadruped');import go2_tuning_base_data as b;s=json.loads(pathlib.Path('workspace/training/quadruped/config/experiments/G_A046_seed43_lin_vel_z_m15.json').read_text(encoding='utf-8'));print(b.spec_problems(s))"

| 칸 | 사양 | 기반 데이터 |
|---|---|---|
| `walking_values` | `[-2.0, -1.75, -1.5]` | `[-2.0, -1.5]` |

`-1.75`(G-A044)는 `WEIGHT_OUTCOME.csv` **19행 어디에도 행이 없다.**
자를 대는 회차의 사전등록이 자를 과장하고 있다.

관문의 공백이 더 문제다 — 옛 A043 계약은 `base_data.spec_problems(SPEC)` 를 부르는데
새 A045/A046 계약은 부르지 않는다. **검사가 뒤로 갔다.**

### 해야 할 일 (순서대로)

1. `A044` 결과가 기반 데이터에 왜 없는지 판정한다 — 병합 누락인가, 자격 미달인가.
   회수물은 `workspace/_keep/` 아래 A044 수확물과 `reports/` 의 A044 판독문을 본다.
2. 위 판정에 따라 `G_A046_...json` 의 `base_data` 를 **기반 데이터에서 생성**한다
   (손으로 적지 않는다). `walk_margin` 도 채운다.
3. `tools/test_go2_g_a045_package_contract.py` 의 `SpecTest` 에
   `self.assertEqual(base_data.spec_problems(spec), [])` 를 두 팔 모두에 넣는다.
4. **v9 로 재발행한다.** v8 ZIP 은 불변이므로 고치지 않는다(발행물 이름에 판을 넣는다).
5. `tools/go2_defect_ledger.py` 의 C-34 를 FIXED 로 내리고 재현을 고침 확인형으로 바꾼다.

## 5. 손대지 말 것

- 발행된 ZIP 의 바이트 (`upload/*/current/`, `upload/*/history/`) — 불변 증거다
- 임계값·판정 문턱 — 빨갛다고 무르지 않는다. 빨강이 맞으면 결함으로 적는다
- `train.py` / `play.py` / `go2_task/` — 규정 R-6, 수정 대상이 아니다
- 러너 고정 표(`PUBLISHED_RUNNERS`, `EXECUTED_RUNNERS`) — 발행본이 재빌드되지 않게 된다
