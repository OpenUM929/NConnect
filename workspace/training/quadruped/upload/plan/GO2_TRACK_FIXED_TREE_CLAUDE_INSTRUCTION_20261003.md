# 사용자 지시 기반 트랙 고정·단일변수 탐색트리 — Claude Code 상세 계획서 작성 지시

## 최신 사용자 요청 (원문)
현재 튜닝 정책을 만든는데 네 행동이 매우 실망스러워. 테스트 방법이 너무 이상해. 논리적이지도 않고 이상한 논리로 행동해 그렇기에 내가 지시할테니 내 지시를 기반으로 테스트해줘.
1. 트랙 값은 현재 결과들을 기준으로 트랙만 변경했을때 가장 좋은 값으로 변경해줘.
2. 트랙을 고정값으로 하고 다른 보상값들의 변화를 주어 계단 험지 등에서 도움이 되는 보상변수의 최적값을 하나씩 변경하면서 찾는 탐색트리를 만들어줘.
3. 위의 내용에 대해 이해한 바를 클로드코드에게 상세 계획서 지시를 진행해줘

## Codex의 이해와 계획 기준
- 트랙은 현재 실험의 `track_lin_vel_xy_exp`다. `track_ang_vel_z_exp`와 혼동하지 않는다.
- 현재 기록상 트랙 선택은 **1.5**. PC2 B1(1.5) 대 track1.4는 다른 보상이 같은 비교이며 내부 proxy 46.77 대 44.72, 10cm ≥2단 85 대 47, 험지 옆걸음 낙상 41 대 55다. 서버 A017→A033의 1.4→1.5 비교와 A033→A042의 1.5→1.6 비교는 별도 계보로 설명한다. 서버와 PC2 수치를 합쳐 효과를 계산하지 않는다. 1.5는 현재 시험 결과에 따른 선택이지 전역 최적성 보장이 아니다.
- 이후 트랙 재탐색을 기본 가지에 넣지 않는다. 다른 보상 항을 하나씩 탐색하고, 해당 항의 개선값이 선택되면 그것을 유지한 부모 설정에서 다음 항을 탐색한다. 형제 노드는 같은 부모에서 한 항만 달라야 한다. 여러 항의 개별 승자들을 미검증 상태로 한꺼번에 합치지 않는다.
- 최신 요청은 탐색 구조를 바꾸라는 지시다. 계단을 단순 보호 대상으로 밀어내지 말고 험지와 함께 개선 목표로 둔다. 모든 조건을 최종 제출 수준으로 만족해야만 탐색한다는 장벽을 추가하지 않는다. 대신 탐색 진행과 최종 채택을 구별하고 행동 간 손실을 총점으로 숨기지 않는다.
- 보상 설정 재사용이며 checkpoint 이어 학습 지시가 아니다. PC2 실제 출발은 현재 B1(A048 보상 계열)이며, 서버 역사 비교군 A033과 구별한다. 다른 출발점으로 몰래 전환하지 않는다.
- 기존 `lin_vel_z_l2=-1.25` 고정·명시 기각값은 이번 '다른 보상'이라는 포괄 표현만으로 자동 해제하지 않는다. 활성 트리는 남은 허용 항으로 완성한다. 고정 해제가 꼭 필요한 가지는 별도 비활성 가지로 표시하고, 이를 이유로 전체 계획을 중단하지 않는다.

필독: 루트/기체 AGENTS.md, GO2_TUNING_ANALYSIS_BRIEF.md, GO2_NOW.md 최신 항목, GO2_REWARD_EVIDENCE_MASTER.md §1-a, reports/GO2_LECTURE_REWARD_REFERENCE.md(§8 원인 기록 재사용), GO2_REWARD_TRIAL_REFERENCE.md, GO2_TUNING_BASE_DATA.md, GO2_REWARD_MECHANISM_FORECAST.md, GO2_G_A060_PC2_THREE_POINT_ANALYSIS_20261003.md, upload/plan/GO2_PC2_DENSE_SWEEP_PROPOSAL_20261002.md 최신 부분. reports/ 및 upload/ 경로는 workspace/training/quadruped/ 기준이다.

선택에 쓰는 정책/대조군 report.html 본문과 env·로그 대응을 직접 확인하고 REPORT_READ_STATUS를 사실대로 적어라. 원본이 없는 과거 run은 규정에 따라 한 번만 공백을 기록하고 기존 로그·평가 근거로 진행한다. 요약만 읽고 READ_MATCHED라 하지 말라. 새 다운로드나 원자료 재계산·진단 실행은 하지 않는다.

계획서 필수 내용:
1. 사용자 요청을 짧고 정확하게 재진술하고, 트랙 1.5 고정 근거와 비교 범위·부작용을 제시한다.
2. 부모 보상 전체 설정, 변경 항, 후보값, 유지 항, 출처를 명시한다. 실제 현재 파일 변경과 계획상 고정은 구분한다.
3. 관측 사실 → 기존 원인 설명의 범위/공백 → 강좌 설명에 따른 방향 예측 → 과거 반례 → 값/폭 선정의 순서를 지킨다. 비용 크기를 낙상의 원인으로 바꾸지 않는다.
4. 동일 비용 대안과 비교해 첫 항·첫 값을 선택한다. 강화 실패면 완화 성공, 작은 변경이면 안전, 미탐색이면 우선 같은 추론을 쓰지 않는다. 값은 시험 설계값으로 표시한다.
5. ASCII 탐색트리와 노드 표를 제공한다. 개선/정체/악화/자료불충분 각각 다음 노드, 부모 복귀, 해당 방향 종료, 다음 변수 이동 조건을 명시한다. 첫 실행 노드는 하나로 특정하고 이후는 결과 조건부로 한다. 전체 조합 격자나 무조건 반복 실행으로 만들지 않는다.
6. 같은 변수 내 후보값을 비교할 때 부모 설정은 고정한다. 승자 선택 후 다음 변수로 넘어갈 때 새 부모를 명시한다. 실패한 자식 값을 다음 부모에 남기지 않는다. 상호작용 때문에 '항별 전역 최적'이 아니라 해당 부모 조건의 관측 최선임을 적는다.
7. G5 10/15cm 실제 오름·완주/낙상·정체, G3 전진/옆걸음 생존과 추종을 함께 보고, G2 우회전·G6 밀침 등 보존할 이득을 정한다. 단순 ≥2단 도달과 완주는 구별한다. 부분 평가를 /70 전수 점수로 쓰지 않는다. 영상/내부 정량/공식 결과를 구분한다.
8. 기존 판정을 소급 변경하지 않는다. 새로운 탐색 가지의 선택 규칙은 실행 전 명시하며, 수치 문턱의 출처와 설계 이유를 쓴다. 미측정 결과를 미리 채우지 않는다.
9. 기존 학습 길이/평가 조건을 유지하며 학습 연장·독립 seed 반복을 핵심 해결책으로 끼워 넣지 않는다. 장비 간 수치를 직접 효과 비교하지 않는다. 기존 실행 중 PC1/PC2 작업을 중단하거나 설정을 덮어쓰지 않는다.
10. 실행 순서·최대 노드 수·시간 산정 근거·중단 조건·필수 report/영상/telemetry 회수를 간단히 명시한다. 잔여 예산 모르면 모른다고 쓴다. 규정 R-6 준수: 배포 학습 경로 변경 금지.
