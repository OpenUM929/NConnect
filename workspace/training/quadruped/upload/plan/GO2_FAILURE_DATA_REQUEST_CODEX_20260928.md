## 1. 요청 범위와 역할

이번 사용자 요청은 이전의 ‘추가 분석 없음’을 **결정에 필요한 데이터 수집 계획과 로컬 분석 범위에서 변경**한다. 같은 영상의 반복 감상이나 무제한 자료 수집을 지시하는 것은 아니다.

- Claude: 기존 자료 조회·실패 사건 분석·수집 가능성 확인·결과 보고. Codex: 후보와 방향·값의 최종 선택. 서버 실행은 사용자 담당.
- A051 철회, lin_vel_z 단독 탐색 종료, 학습 길이 비교 보류, U1/U2 미해결은 유지한다. 계측 요청은 이 결정을 해제하지 않는다.
- 보상 변경·새 학습·전체 69 case 재실행은 이번 계획의 기본 범위가 아니다. 저장 정책을 읽는 진단 재생은 필요성이 확인된 경우에만 별도 준비한다.
- 기존 원자료·실행 사양·ZIP·판정은 불변 보존한다. 결과를 새 채택 판정으로 소급 적용하지 않는다.
- 실제 자료 분석 전에 ARTIFACT_MANAGEMENT.md를 읽고 아래 작업 키의 중복을 확인해 등록한다: `GO2-FAILURE-DATA-20260928`. 이번 Codex 작업은 계획서만 작성하며 정본 원장은 Claude가 관리한다.

## 4. 1단계 — 로컬 자료만으로 사건표 작성

### 4-1. 범위
- 핵심: A048의 `rough_lateral`, 10cm/15cm 오르기. case 정본 이름은 registry에서 확인한다(`stairs_*_down` 문자열만으로 하강이라 부르지 않는다).
- 비교: G3는 A033, 계단은 A043. A050의 기존 사건표는 반례로 재사용한다. 다른 정책 전수 재분석은 해당 비교가 실제 결정을 바꿀 때만 추가한다.
- 기존 3평가 seed·32개체 전체를 집계한다. 유효 기록 수와 누락 수를 별도로 기록한다. 동일 학습 seed의 평가 반복을 독립 학습 반복으로 표현하지 않는다.
- 원 CSV를 반복해서 읽지 말고 case 단위 한 번 읽어 필요한 열과 사건표를 재사용한다. 무거운 작업은 한 프로세스씩, 외부 timeout 및 자식 timeout, 종료코드·실행/생략 수·시간을 기록한다. OOM 작업을 자동 반복하지 않는다.

### 4-2. 사건과 비교 창
- 기존 낙상 정의와 종료 사건을 그대로 적용한다. ‘자세 조건 최초 위반’, ‘연속 시간 충족’, ‘몸통 접촉 종료’를 각각 기록한다. 종료 직후 reset된 다음 episode 자료를 섞지 않는다.
- 계단은 첫 모서리 접근, 첫 발 접촉(없으면 UNKNOWN), 몸통 하강, 정체, 종료, 실제 단 통과 시각을 구분한다. 몸통 중심이 모서리를 지났다고 발이 디뎠다고 하지 않는다.
- 새 진단의 기본 창은 사건 전 1초~후 0.5초다. 종료로 짧아지면 실제 유효 길이를 표시하고 연장·보간으로 채우지 않는다. 이 창은 분석 편의 설정이지 채택 문턱이 아니다.
- 성공 대조는 같은 정책·case·평가 seed 안에서 비슷한 모서리/진행 위치를 우선한다. 전복 대조도 같은 지형 구간을 우선하며 불가능하면 비교 한계를 적는다. 단순히 실패 시간과 같은 초의 생존 로봇을 완전한 대조라 부르지 않는다.
- 낙상 유형은 기존 분류를 보존하고 중복/우선순위 규칙을 명시한다. 분류 합계와 원 판정 낙상 수를 대조하며 불일치하면 원인부터 해결한다.

### 4-3. 산출할 핵심 행
`policy, checkpoint_sha, case, eval_seed, env_id, episode_id, outcome, fall_channel, onset_time, termination_time, event_order, command, signed_velocity, gravity, height, forward_progress, source_path, valid_window, missing_reason`.

기존 저장 채널이 없으면 null+이유다. root_z 차분으로 body_vz를, 기울기 차분으로 body angular velocity를 만들어 원 채널처럼 쓰지 않는다. 영상과 env_id 대응이 없으면 별도 표본으로 유지한다.

## 5. 2단계 — 결측 중 선택을 가르는 것만 진단 재생으로 확보

### 실행 경계
이 단계는 **서버 실행 승인이나 새 학습 요청이 아니다**. Claude는 먼저 필요한 채널이 현재 배포/별도 evaluator에서 읽기 가능한지 확인하고, 로컬에서 가능한 일부터 수행한다. 새 서버가 필요하면 시간·용량·회수 예산과 정확한 수집 목록을 제시한다. 비용은 기존 학습 95분을 재사용하지 말고 재생 smoke 실측으로 추산한다.

- 배포 train.py/play.py/task/reward 원본을 수정하지 않는다. 도구 설치·외부 서비스 연결 없이, 허용 범위의 별도 읽기 전용 계측 모듈로 저장 정책을 평가한다. 규정상 권한이 불명인 구성 변경은 실행하지 않고 구체적으로 보고한다.
- reward manager를 추가 호출해 상태를 바꾸거나 센서 갱신 순서를 바꾸지 않는다. 원 계산값을 읽거나 독립 배열에서 산술한다. 정책 action·관측·reset·명령·지형 동작은 바꾸지 않는다.
- 새 계측은 과거 평가와 별도 버전·출력 경로를 가진다. 원 정책 SHA·env·registry·evaluator·명령·seed·num_envs·지형·초기 상태·카메라를 기록한다.

### 최소 실행 매트릭스와 중단점
1. 정책은 A048, case는 rough_lateral 및 10/15cm 오르기부터. 기존 평가 seed 중 실패가 기록된 seed를 사건표로 선택하고 선택 이유를 기록한다. 실패를 찾기 위한 선택 표본이며 실패율 추정용이 아니다.
2. 과거 env_id 재현을 시도할 때는 원 num_envs와 초기화 순서를 보존한다. 1대로 줄이거나 같은 seed만 쓰고 같은 로봇이 재현됐다고 주장하지 않는다. 재현 불일치면 새 진단 rollout으로 분리한다.
3. 제어 주기마다 핵심 수치 기록, 영상은 실패 전후가 보이도록 버퍼 또는 전체 짧은 rollout 저장. 접촉 센서의 갱신 주기·필터·단위를 기록한다. 더 빠른 접촉이 누락될 수 있으면 불명 처리하며 무조건 substep 전량 저장하지 않는다.
4. 첫 재생에서 필요한 사건이 포착됐으면 반복하지 않는다. 없으면 case당 추가 1평가 seed까지만 계획 범위로 둔다. 그래도 없으면 NOT_OBSERVED로 종료한다. 무한 seed 탐색 금지.
5. A043 계단 또는 A033 험지의 새 대조 재생은 A048에서 특정 가설이 드러나고 기존 대조 자료로 비교할 수 없을 때만 추가한다. 조건부 대조 비용을 별도로 적는다.

| 동작 | action, previous action, 처리 후 target(제공되면), action clipping | 발 떨림과 정책 출력 급변 구분. 영상 움직임만으로 action_rate를 단정하지 않음 |
| 보상 | 활성 항 원값·weight·weighted value·dt 처리, command gate, air_time threshold | feet_air_time 착지 시 음/양 기여, 추종과 안정성 비용을 사건 창에서 비교 |
| 성과 | signed tracking error, 경로 진행량, 등반·정체·자세·종료 | 보상이 좋아 보이는 것과 실제 과제 수행 구분 |

측면은 발-모서리와 몸통 높이, 사선/정면은 좌우 지지·전복을 보는 데 사용한다. 가능한 한 같은 rollout에 동기 카메라를 쓴다. 별도 재생 영상이면 동일 사건으로 합치지 않는다. 센서가 없는 접촉·마찰·발 여유 높이는 영상으로 확정하지 않는다.

## 6. 데이터에서 후보로 이어지는 판단표

아래는 후보를 만드는 가설이지 자동 처방이 아니다. 필요한 동작이 보상에서 불리하다는 관측만으로 학습 개선을 보장하지 않는다.

| 데이터 패턴 | 먼저 비교할 가설 | 반대 확인·보존할 이득 |
|---|---|---|
| 계단 조정 걸음의 착지 air_time이 threshold 아래이고, 성공에도 짧은 조정 걸음이 필요함 | feet_air_time 완화가 필요한 조정 걸음 비용을 줄이는지 | 무익한 잔걸음 강화·기존 완화 실패와 기준 설정 차이, 평지/험지 보행 유지 |
| 긴 유각 후 지지 발 부족이 전복/하강보다 먼저 반복됨 | 체공시간 인상 지지 감소, 완화 가능성 비교 | 접촉 결측·미끄러짐 대안; 체공시간과 발 높이는 별개 |
| 발 충돌 상태에서 명령 추종 오차와 전진 동작이 지속되고, 성공은 일시적 감속·자세 조정함 | track 완화로 과제 간 우선순위 조정 가능성 | 충돌은 속도 가중치 원인이라는 증거가 아님. 성공도 동일 오차인지, G1/G2/G3 추종 손실 위험 |
| 접촉/전복 전부터 action 차분이 급증하고 성공 대조에는 없음 | action_rate 강화 가능성 | action 급변이 필요한 균형 회복일 수 있음. 강화가 발 위치 조정을 막는지 |
| 필요한 발 조정 시 action 변화가 제한되고 target 반응이 지연됨 | action_rate 완화 또는 다른 동작 제약 가설 | 단순 지연만으로 비용 항 원인 확정 금지, A018 이력·진동 위험 반영 |
| G3에서 빠른 몸통 회전이 지지 상실보다 먼저 반복됨 | 회전 비용 조정 가설 재비교 | 외력/접촉 뒤 회전이면 원인 해석 약함. A038·A041 계단 손실 때문에 A051 자동 부활 금지 |
| 관절 포화·한계 접촉이 붕괴보다 먼저임 | 구동/자세/발 경로 경쟁 가설 | 토크 부족 확정 금지. U1 미해결 항을 바꾸지 않음 |

강좌 설명 → 실제 식 → 사건 관측 → 경쟁 가설 → 기존 반례 → 보존할 A048 이득 → 값/폭 선택 이유 → 같은 비용의 대안 → 결과별 다음 결정의 한 표로 최종 제출한다. 고정 궤적에서 가중치를 바꾼 부분 보상 합을 재학습 성능 예측이나 후보 순위 점수로 쓰지 않는다.

인과 확정은 후보 선정의 필요조건이 아니다. 다만 관측 결측을 안전이나 긍정 근거로 바꾸지 않는다. 데이터가 불명이어도 강좌·식·기존 실험을 함께 비교해 탐색 우선순위를 제안할 수 있으며, 수집 완료 자체를 새로운 영구 관문으로 만들지 않는다.
