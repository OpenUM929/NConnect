19. 생각하는 로봇, 완성

느린 대뇌(LLM)는 한 번 생각하는 데 2~3초가 걸리지만, 빠른 소뇌(정책)는 1초에 50번씩 움직임을 제어해요.대뇌가 생각하는 동안에도 소뇌가 쉬지 않고 움직여, 멈춤 없이 스스로 판단하는 로봇이 완성돼요.

①

생각 열기

LLM이 계산한 속도 벡터를 보행 정책에 그대로 넣어주면 바로 로봇이 움직일 것 같죠?하지만 대뇌(LLM)가 생각하는 2~3초 동안 소뇌(제어 코드)가 멈추기 때문에, 로봇은 제대로 움직일 수 없어요.

한 번 일하는 데초당
정책 .pt (소뇌)0.02초50회
LLM (대뇌)2~3초0.3~0.5회
대뇌 · LLM 0번 생각 · 한 번에 2.5초
소뇌 · 정책 0번 움직임 · 50Hz
❌ 같은 루프: LLM 호출이 빠른 제어 루프 안에 있어요. 생각시키면 로봇이 어떻게 되는지 보세요.

사람은 걸으면서 저녁 메뉴를 고민해요

사람도 똑같아요. 느린 뇌와 빠른 몸을 갖고 있죠. 그런데 걸으면서 "오늘 저녁 뭐 먹지?" 같은 복잡한 생각을 해도 다리는 한 번도 안 멈춰요.비결은 분리예요. 뇌는 대뇌(전략·판단)와 소뇌(운동 제어·반사)로 일을 나눠요. 대뇌가 저녁 메뉴를 고민하는 동안, 소뇌는 "걷는다"는 명령 하나를 계속 붙들고 근육을 미세하게 조종하죠.위층의 느린 판단이 아래층의 실시간 제어를 방해하지 않게 분리돼 있는 거예요. 사람의 몸은 이미 답을 알고 있는 셈이죠.

로봇이 빠지기 쉬운 함정, 직렬 대기

그런데 이걸 로봇으로 옮길 때, 처음엔 누구나 같은 실수를 해요. 물어보고 → 답을 기다렸다가 → 움직이는 직렬 호출이에요.LLM(대뇌)의 답을 기다리는 2~3초 동안, 로봇은 다음 걸음을 내딛지 못하고 멍하니 서 있어요. 보행 정책은 20ms마다 새 명령을 받아야 하니, 그 2~3초 사이에 제어 기회가 100번 넘게 사라져요.문제는 답의 품질이 아니라 기다리는 시간이고, 그 결과는 균형을 잃고 쓰러지는 로봇이에요.

해결책은 대뇌를 서두르게 하는 게 아니라, 사람 뇌처럼 두 뇌를 따로 돌리는 것이에요.빠른 소뇌는 마지막 명령을 읽으며 쉬지 않고 걷고, 느린 대뇌는 뒤에서 생각하다 목표만 갱신해요. 이 구조를 오늘 직접 만들어 돌려봐요.
②

개념 만나기

생각 열기에서 본 사람 뇌의 분업을, 이제 코드 구조로 옮겨요.

PART 1 두 루프

먼저, 루프란

프로그램에서 같은 일을 계속 반복하는 흐름을 루프(loop)라고 해요. 파이썬의 while이나 for가 만드는 그 반복이에요.로봇 제어는 처음부터 끝까지 루프예요. "센서값 읽기 → 다음 동작 정하기 → 관절에 명령" 이 한 바퀴를 1초에 50번 돌아요. 한 바퀴가 20ms인 거죠. 여러분이 학습시킨 보행 정책도 이 반복 안에서 돌고 있었어요.아래에서 그 한 바퀴를 직접 돌려봐요. 관찰용으로 천천히 돌린 뒤 실제 속도로 바꿔보면, 이 반복이 얼마나 빠른지 눈으로 알 수 있어요.오늘의 두 루프는 이 반복을 두 개로 나눈다는 뜻이에요. 20ms마다 도는 빠른 루프 하나와, 2~3초마다 도는 느린 루프 하나요.

보기 좋게 100배 느리게 돌린 모습이에요. 실제 로봇은 이 한 바퀴를 20ms에 끝내요.

지금까지 9바퀴 · 실제 로봇은 1초에 50바퀴를 돌아요

LLM을 직접 부르지 않는 빠른 루프

빠른 루프(소뇌) 안에서 LLM을 직접 부르면, 답이 올 때까지 제어가 함께 멈춰요. 그래서 느린 대뇌는 백그라운드에서 돌리고, 결과가 나오면 공유 상태 하나만 갱신해요.소뇌는 대뇌가 생각하는 동안에도 직전 명령대로 계속 걸어요. 두 루프가 만나는 곳은 이 공유 상태(현재 명령) 하나뿐이에요. 대뇌는 가끔 그걸 새로 쓰고, 소뇌는 매 순간 읽어요. 목표가 아직 없을 때도 소뇌는 제자리에서 균형을 계속 잡고요.

백그라운드 스레드, 프로그램 안의 두 번째 일꾼

여기서 "백그라운드에서 돌린다"를 가능하게 하는 도구가 스레드(thread)예요.보통 프로그램은 한 줄기로만 흘러요. 윗줄이 끝나야 아랫줄이 실행되죠. 그래서 오래 걸리는 일(LLM 호출)을 만나면 그 줄에서 프로그램 전체가 함께 기다려요. 이게 방금 본 직렬 대기예요.threading.Thread(...)는 프로그램 안에 일꾼을 한 명 더 만들어요. 오래 걸리는 일은 새 일꾼에게 맡겨 뒤(백그라운드)에서 돌리고, 원래 줄기는 멈추지 않고 계속 가는 거예요. 이렇게 서로 기다리지 않고 각자 돌아가는 방식을 비동기(asynchronous)라고 해요.오늘은 이 도구로 느린 대뇌 전체를 백그라운드 스레드에 태워요.

소뇌(정책)는 1초에 약 50번, 현재 명령을 읽고 그대로 움직여요. 대뇌가 뭘 하든 한 번도 멈추지 않아요.

PART 2 계층 나누기

LLM에게 운전대 말고 지도를

LLM에게 "앞으로 0.5m/s로 가"처럼 걸어가는 속도를 직접 지정할 수 있어요. 그런데 이건 LLM이 잘하는 일이 아니에요."장애물을 피해 목표까지 최단 경로"는 지도 위에서 좌표·거리·각도만 따지는 계산이에요. 말뜻을 이해할 필요 없이 숫자만 맞추면 되죠(이런 걸 기하 계산이라고 해요). 이런 건 LLM보다 전용 알고리즘이 훨씬 빠르고 정확해요. A* 같은 경로 탐색 알고리즘은 수 밀리초 만에 최단 경로를 딱 찾아내고, "다음 지점으로 방향·속도 맞추기"도 삼각함수 몇 줄이면 끝나거든요.그럼 LLM에겐 뭘 맡길까요? 알고리즘으로 못 푸는 것. 우선순위, 위험과 보상의 저울질, 사람 의도의 해석이에요. 그래서 실전 시스템은 층을 더 나눠요.

위로 갈수록 똑똑하고 느리고, 아래로 갈수록 단순하고 빨라요. 각 층은 바로 아래층에게 "목표"만 넘기고, 어떻게 할지는 맡겨요.회사 조직과 비슷해요. 사장이 직원 손을 일일이 움직이지 않듯이요.그리고 이 계층 나누기는 교실용 예시가 아니라 실제 로보틱스의 표준 설계예요.

PART 3 현실의 로봇

이건 우리만의 방식이 아니에요

방금 나눈 4개 층은 특별한 게 아니라, 복잡한 로봇이라면 어디서나 쓰는 정석이에요.원리는 하나예요. 위층엔 느리지만 똑똑한 판단을, 아래층엔 빠르지만 단순한 제어를 두고, 각 층은 자기가 잘하는 일만 맡아요. 자율주행차부터 휴머노이드 로봇까지, 실제 시스템이 이렇게 층을 쌓아요.

자율주행차경로·행동 계획조향·가감속 제어

오늘 배운 두 루프와 계층 구조가 이 모든 시스템의 공통 뼈대예요. 이전 강의에서 만든 검증·clamp·복구 같은 안전장치도 각 층에 그대로 들어가죠. 여러분이 만들어온 게 장난감이 아니라, 같은 설계 원리가 그대로 확장된 거예요.
④

직접 해보기

"생각하는 로봇"을 실제로 움직여봐요. 느린 대뇌(LLM)가 목표를 정하고, 빠른 소뇌(정책)가 쉬지 않고 걸어 도착하는 모습을 눈으로 확인해요.

예제 돌리는 법

실습에 쓰는 코드는 두 파일이에요. 어려운 제어·시뮬은 robot_sim.py가 통째로 맡고(수정하지 않아요), 두 루프까지 이미 짜여 있어요.그래서 여러분이 채울 건 딱 두 가지예요.
① 내가 만든 정책 파일 my_test.pt를 examples/19 폴더에 넣기
② 19-1.py를 열어 STRATEGY(전략 문장)와 POLICY(내 파일 이름), 이 두 줄만 고치기씬은 단순해요. 바닥에 3색 큐브(노랑·초록·빨강)를 놓고, 느린 대뇌(LLM)가 전략을 읽어 정한 순서대로 걸어가 방문해요. (아래 19-1.py는 구조만 보여주는 간략 버전이에요.)한 가지 달라진 점이 있어요. 앞에서는 내 컴퓨터에서 돌아가는 LLM을 썼지만, 이번엔 Gemini Flash를 불러 써요. 이유는 두 가지예요.① 시뮬레이터가 GPU를 거의 다 쓰고 있어요. 같은 GPU에 LLM까지 올리면 서로 자원을 다투다 시뮬이 느려지고 화면이 끊겨요.② 이번 판단은 "전략 문장을 읽고 방문 순서를 정하는" 일이에요. 이런 자연어 판단에는 크고 범용적인 모델이 더 안정적이라, 그 능력을 잠깐 빌려 오는 거예요.바뀐 건 부르는 주소와 모델 이름뿐이에요. "자연어를 보내 판단을 받아온다"는 구조는 앞에서 만든 것과 똑같아요.

19-1.py, 두 루프의 핵심 구조
줄을 누르면 해설
import threadingfrom robot_sim import World, Robot, Cube STRATEGY = "노란 큐브부터, 그다음 초록, 마지막에 빨강 순서로 가줘" # ← 내가 채우는 전략POLICY = "my_test.pt" # ← 내가 채우는 정책 파일 world = World()robot = Robot(world, POLICY)cubes = {"yellow": Cube(world, 8, 6, "yellow"), "green": Cube(world, 16, 0, "green"), "red": Cube(world, 8, -6, "red")}visited = []brain = {"next": None} def think(): try: brain["next"] = ask_next(STRATEGY, list(visited)) except Exception: remaining = [c for c in cubes if c not in visited] brain["next"] = remaining[0] if remaining else None threading.Thread(target=think, daemon=True).start()robot.stand(30) target = Nonewhile world.is_running(): if target is None and brain["next"] is not None: target, brain["next"] = brain["next"], None  if target is not None: robot.walk_to(cubes[target].pos) if robot.reached(cubes[target].pos): visited.append(target) target = None threading.Thread(target=think, daemon=True).start() else: robot.hold()  world.step()
// 표시된 줄을 클릭하면 해설
밑줄 친 줄을 클릭하면 무슨 일을 하는지 짚어줄게요.

제어·시뮬은 별도 파일에, robot_sim.py (제공)

위 walk_to·reached가 실제로 하는 일이에요. 목표를 속도 벡터로 바꾸고(제어), 내 정책에 넣어 관절을 움직여요. 이 파일은 건드리지 않아요. 오늘의 핵심은 19-1.py의 두 루프예요.

robot_sim.py (제공, 수정 X)
줄을 누르면 해설
class Robot: def walk_to(self, goal): vx, wz = waypoint_to_velocity(self.pos, self.yaw, goal) action = self.policy(self.observe(vx, wz)) self.apply(action)  def reached(self, goal, tol=0.6): return distance(self.pos, goal) < tol

미션, 3색 큐브를 순서대로

🥚
기본 · 도착했는지 거리로 판정
로봇이 큐브에 닿았는지는 평면 거리로 봐요(tol=0.6보다 가까우면 도착). 거리를 계산해봐요.
import math

def distance(a, b):
    return math.hypot(a[0] - b[0], a[1] - b[1])

robot = (3.0, 1.0)
cube  = (3.2, 1.4)
d = distance(robot, cube)
print(round(d, 2), "→ 도착" if d < 0.6 else "→ 아직 멀어요")
출력된 거리 값을 입력해보세요.
내 답
정답 → 0.45 (0.6보다 작으니 "도착")
1math.hypot(dx, dy)가 평면 거리(빗변)를 구해줘요.
2dx=0.2, dy=0.4 → 거리는 0.4~0.5 사이예요.
🐣
보통 · Gemini 실패 시 fallback
대뇌(Gemini)가 실패하면 남은 큐브 중 첫 번째로 되돌아가요. 몇 개가 후보로 남는지 봐요.
cubes = ["노랑", "초록", "빨강"]
visited = ["노랑"]

remaining = [c for c in cubes if c not in visited]
print("남은 큐브 수:", len(remaining))
print("fallback이 고를 큐브:", remaining[0])
출력된 남은 큐브 수를 입력해보세요.
내 답
정답 → 2 (초록·빨강). fallback은 remaining[0]=초록을 골라요.
1[c for c in cubes if c not in visited]는 아직 안 간 큐브만 남겨요.
2셋 중 하나(노랑)를 이미 갔으니 몇 개가 남을까요?
🐥
도전 · 공유 상태 꺼내오기
두 루프는 brain["next"] 하나로 만나요. 빠른 루프가 목표를 꺼내 오며 자리를 비우는 걸 확인해봐요.
brain = {"next": 2}     # 대뇌가 2번 큐브로 정해뒀어요
target = None

# 빠른 루프: 준비됐으면 꺼내오고, 자리는 비워요
if target is None and brain["next"] is not None:
    target, brain["next"] = brain["next"], None

print("target =", target, "/ brain[next] =", brain["next"])
스왑 뒤 target 값을 입력해보세요.
내 답
정답 → 2 (그리고 brain[next]는 None)
1target, brain["next"] = brain["next"], None은 한 줄로 값을 옮기고 자리를 비워요.
2target에는 brain이 갖고 있던 값이, brain["next"]에는 None이 들어가요.

실행 도중 Gemini 호출을 일부러 실패시켜 소뇌가 계속 가는지 확인해봐요.

2[대뇌]에 "Gemini 실패 → 규칙 fallback"이 찍혀도 [소뇌]가 직전 목표로 계속 가는지 확인해요.
3원래 모델 이름으로 되돌리면 [대뇌]가 다시 Gemini로 판단하며 회복되는지도 보세요.

전략(①) / 제어(③) / 정책(④). ② 경로는 큐브로 직진이라 이 예제엔 생략됐어요.

19강 한눈에 정리

  • 정책 50Hz vs LLM 0.5Hz. 100배 속도차가 모든 설계를 결정해요
  • 빠른 루프는 절대 멈추지 않아요. 느린 대뇌는 공유된 "현재 명령"을 갱신할 뿐이에요
  • 더 좋은 분업은 계층이에요. 전략(LLM) → 경로(A*) → 제어(기하) → 정책(.pt)
  • LLM에게는 알고리즘으로 못 푸는 일만 맡겨요. 우선순위·저울질·의도 해석이에요
  • 실패 시 이전 명령 유지. 대뇌가 멈춰도 소뇌는 계속 가요
  • 실제 로봇 시스템이 정확히 이 구조예요. 맨 아래층은 여러분이 키운 정책이에요
