04. 로봇 불러오기

파일 하나에 로봇 한 대가 담겨 있다면, 그 안은 어떻게 생겼을까요? 파일을 화면에 불러와 부품을 하나씩 열어 봐요.

①

생각 열기

우리가 물체를 올려놓는 3D 공간을 스테이지라고 불러요. 지금까지는 스테이지에 공이나 상자처럼 단순한 도형만 올려봤죠. 오늘은 로봇을 불러올 차례예요. 이번 대회에서 우리가 쓸 로봇은 두 종류인데, 어떤 것이 다를까요?

네 발로 걷는 로봇과 두 발로 걷는 로봇

하나는 네 발 달린 사족보행 로봇이에요. 강아지처럼 땅을 딛고 다녀요. 다른 하나는 사람의 형태로 두 다리로 걷는 휴머노이드 로봇이에요. 두 팔까지 달려 있어요. 두 로봇 모두 여러 개의 관절을 따로 움직일 수 있는데, 이렇게 독립적으로 움직일 수 있는 관절 수를 자유도(DoF)라고 해요.

USD, 로봇의 디지털 설계도

Isaac Sim에서 모든 물체는 USD(범용 장면 표현) 형식으로 저장돼요. 단순한 3D 모델 파일이 아니라, 다음 정보를 모두 담고 있어요.

USD는 원래 픽사(Pixar)가 장편 애니메이션용으로 만든 포맷인데, 엔비디아가 로봇 공학에 들여왔어요. 로봇을 부품 단위로 나눠 저장하는 게 핵심이에요. 그래서 위 정보들을 부품마다 담을 수 있고, 다음 강에서 다룰 관절 제어도 이 구조 위에서 이뤄져요.

prim_path, 부품 하나를 정확히 가리키는 주소

USD 안에서 모든 부품은 슬래시로 구분된 경로로 식별돼요. 파일 시스템의 디렉터리와 똑같은 구조예요. 예를 들어, /World/H1은 "World라는 스테이지 위에 올린 휴머노이드 로봇"을 가리켜요. 여기에 한 단계 더 붙인 /World/H1/Joints/left_shoulder_pitch는 "그 로봇의 왼쪽 어깨 pitch 관절"이에요. 이 경로 하나로 어느 부품이든 직접 잡을 수 있어요.

칸이 하나씩 늘어날 때마다 경로가 한 단계 깊어져요. 금색 칸이 그 줄에서 새로 붙은 이름이에요.

휴머노이드 로봇 전체. 관절 19개가 한 덩어리(Articulation)로 묶여요.
경로는 대문자와 소문자를 서로 다른 글자로 봐요. /World/H1과 /World/h1은 우리 눈엔 비슷해 보여도 컴퓨터에겐 아예 다른 주소예요. 그래서 대문자 하나만 소문자로 잘못 적어도 "그런 prim이 없다"는 에러가 나요. 띄어쓰기도 쓸 수 없고, 대신 언더바(_)로 이어 붙여요. 즉, /World/My H1은 틀렸고, /World/My_H1이 맞아요. 익숙해지면 prim_path만 봐도 USD 트리 구조가 머릿속에 그려져요.

roll, pitch, yaw, 관절이 도는 세 방향

앞의 트리에서 본 것처럼, 고관절(hip)은 yaw, roll, pitch 세 관절로 나뉘어요. roll, pitch, yaw는 원래 비행기에서 온 말이에요.셋 다 회전이라는 점은 같고, 어느 축을 중심으로 도느냐만 달라요.roll은 앞뒤로 뻗은 X축을 중심으로 돌아요. 다리를 옆으로 들어 올렸다 내리는 움직임이에요.pitch는 좌우로 뻗은 Y축을 중심으로 돌아요. 걸을 때처럼 다리를 앞뒤로 움직여요.yaw는 위로 선 Z축을 중심으로 돌아요. 발끝이 안팎을 향하게 다리를 비틀어요.아래에서 하나씩 돌려보면 차이가 한눈에 들어와요.

골반은 고정이라 다리만 움직여요. 버튼은 자동으로 돌려 주고, 슬라이더는 원하는 각도로 직접 맞출 때 써요. 화면을 끌면 보는 방향이 바뀌어요.
버튼을 누르면 그 축이 굵게 켜지고, 곡선 화살표가 도는 방향을 보여줘요. 오른쪽 아래 기준 축은 X, Y, Z 방향을 반듯하게 보여줘요.

Articulation, 관절 전체를 잡는 손잡이 하나

오늘 사용할 휴머노이드 로봇은 관절이 19개예요. 이 관절들은 USD 안에서 이미 하나의 트리로 이어져 있어요. 이렇게 연결된 관절 묶음을 Articulation(아티큘레이션)이라고 해요. 다만 불러오기만 해선 관절을 코드로 움직일 손잡이가 없어요. 관절 19개를 한 번에 잡아 명령하는 하나의 제어 핸들을 만들어주는 도구가 SingleArticulation이에요. 아래 위젯은 팔 하나로 이 원리를 보여줘요. 휴머노이드 로봇 전체도 관절이 똑같이 한 덩어리로 묶여요.

○ 부품 모음, 손잡이 없음
관절은 이미 이어져 있지만, 코드로 잡을 손잡이가 아직 없어요. 명령을 보낼 창구가 없어서 "팔 들어 올리기"가 로봇에 닿지 않아요.
엔비디아가 배포한 공식 USD 로봇은 관절 트리(ArticulationRoot)가 이미 설정돼 있어요. 직접 만든 로봇이라면 이 트리를 따로 잡아줘야 하지만, 이번 강에선 신경 쓰지 않아도 돼요. 다만 관절을 코드로 잡을 손잡이(SingleArticulation 등록)는 그것과 별개로 우리가 만들어야 해요.

get_assets_root_path(), 에셋 경로를 안전하게 얻기

엔비디아는 공식 로봇 USD 파일들을 AWS 클라우드에 공개해뒀어요. 로봇·물체·환경·재질처럼 시뮬레이션에 가져다 쓰는 이 파일들을 에셋(asset)이라고 불러요. 그 URL을 코드에 그대로 적어두면 Isaac Sim 버전이 바뀔 때 경로가 어긋날 수 있어요. 대신 get_assets_root_path() 함수를 쓰면 버전에 맞는 에셋 경로를 알아서 받아와요.

두 로봇 한 번에 불러오기

USD 파일을 스테이지에 참조(Reference)로 올린 뒤 SingleArticulation으로 등록해요. 바닥과 겹치지 않게 살짝 띄우는 것이 중요해요. 두 발로 서 있는 휴머노이드 로봇은 높게(1.05), 사족보행 로봇은 낮게(0.5) 둬요.

▶ Play 직후 로봇이 주저앉는 이유

스크립트를 실행하면 로봇이 서 있지만, ▶ Play로 물리가 돌기 시작하면 두 로봇 모두 그대로 바닥에 주저앉아요. 버그가 아니라 정상이에요. 지금 코드는 로봇을 스테이지에 올리기만 했을 뿐, 관절에 힘을 줘 자세를 잡아주는 제어기가 아직 없거든요. 전원을 끈 실제 로봇이 힘없이 무너지는 것과 똑같아요. 특히 휴머노이드 로봇은 가만히 서 있는 것조차 끊임없이 균형을 잡아야 해서, 제어기 없이는 더더욱 버티지 못해요.

주저앉는 건 실패가 아니라 출발점이에요. ■ Stop을 누르면 불러온 자세로 돌아오니, 이 강에서는 그대로 두고 구조를 살펴봐요. 스스로 균형을 잡고 서는 건 훨씬 뒤 강화학습에서 다뤄요.

보통 · 삼각형 대형
120° 간격, 반경 1m 정삼각형 꼭짓점마다 사족보행 로봇을 세우고, 이웃한 두 대 사이 거리를 재요
import omni.usd
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.utils.stage import add_reference_to_stage
from isaacsim.core.prims import SingleArticulation
from isaacsim.storage.native import get_assets_root_path

if World.instance() is not None:
    World.instance().clear_instance()
omni.usd.get_context().new_stage()
world = World(stage_units_in_meters=1.0)
world.scene.add_default_ground_plane()

assets_root = get_assets_root_path()
go2_usd = assets_root + "/Isaac/Robots/Unitree/Go2/go2.usd"

dogs = []
for i in range(3):
    theta = np.deg2rad(90 + i * 120)
    x, y = np.cos(theta), np.sin(theta)
    add_reference_to_stage(usd_path=go2_usd, prim_path=f"/World/Go2_{i}")
    dogs.append(world.scene.add(SingleArticulation(
        prim_path=f"/World/Go2_{i}", name=f"go2_dog_{i}",
        position=np.array([x, y, 0.5]))))

import asyncio
async def run():
    await world.reset_async()
    p0 = dogs[0].get_world_pose()[0]
    p1 = dogs[1].get_world_pose()[0]
    side = float(np.linalg.norm(p0[:2] - p1[:2]))
    print(f"이웃한 두 로봇 사이 거리 = {side:.2f} m")

asyncio.ensure_future(run())
120° 간격으로 반경 1m 원 위에 세 대를 세웠어요. 이웃한 두 로봇 사이 거리는 몇 m일까요?
내 답m
정답 → 약 1.73 m. 반경보다 길어요. 원 위에서 120°나 떨어져 있으니까요.
1정삼각형 꼭짓점은 120° 간격이에요. 세 점이 원 위에 어떻게 놓이는지 종이에 그려봐요.
2np.cos(θ), np.sin(θ)로 반경 1m 원 위 좌표를 구해요.
3반경이 1m니까 두 로봇 사이 거리가 1m보다 길지 짧을지 먼저 어림해봐요.

중력을 0으로 끄고 휴머노이드 로봇을 띄워, 150스텝 뒤에도 그대로 있는지 확인해요
import asyncio
import omni.usd
import omni.kit.app
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.utils.stage import add_reference_to_stage
from isaacsim.core.prims import SingleArticulation
from isaacsim.storage.native import get_assets_root_path

async def main():
    if World.instance() is not None:
        World.instance().clear_instance()
    omni.usd.get_context().new_stage()
    world = World(stage_units_in_meters=1.0)
    world.scene.add_default_ground_plane()
    world.get_physics_context().set_gravity(0.0)

    assets_root = get_assets_root_path()
    h1_usd = assets_root + "/Isaac/Robots/Unitree/H1/h1.usd"
    add_reference_to_stage(usd_path=h1_usd, prim_path="/World/H1")
    h1 = world.scene.add(SingleArticulation(
        prim_path="/World/H1", name="h1_humanoid",
        position=np.array([0, 0, 2.0])))

    await world.reset_async()
    for _ in range(150):
        world.step(render=False)
        await omni.kit.app.get_app().next_update_async()
    z = h1.get_world_pose()[0][2]
    print(f"무중력 150스텝 뒤 높이 Z = {z:.1f}")

asyncio.ensure_future(main())

세 대를 1.5m 간격으로 세우고, get_object("go2_dog_2")로 그중 한 대만 다시 찾아요. 그 로봇의 x 좌표는?
내 답m
정답 → 약 3.0 m. 이름을 붙여둔 덕에 여러 대 중에서 원하는 로봇만 골라 다룰 수 있어요.
1name은 코드에서 그 로봇을 다시 부를 때 쓰는 별칭이에요. 주소인 prim_path와는 쓰임이 달라요.
2이름 끝에 붙은 번호는 for문의 i와 같아요. go2_dog_2는 몇 번째로 세운 로봇일까요.
3get_world_pose()[0]은 [x, y, z]를 돌려줘요. x는 그중 첫 칸이에요.

4강 한눈에 정리

  • USD는 로봇의 디지털 설계도 파일이에요. 관절, 무게, 외형, 센서를 모두 담아요
  • prim_path는 USD 안 부품 주소예요. /World/H1처럼 슬래시로 트리 구조를 따라가요
  • SingleArticulation으로 묶어야 관절을 제어할 수 있어요. 휴머노이드 로봇의 관절 19개가 하나의 손잡이로 묶여요
  • 관절이 도는 세 방향은 roll, pitch, yaw예요. 다리를 옆으로 들어 올리는 roll, 앞뒤로 움직이는 pitch, 발끝이 안팎을 향하게 비트는 yaw예요
  • URL은 직접 적지 말고 get_assets_root_path()를 써요. 버전이 바뀌어도 안 깨져요
  • 불러오기만으론 로봇이 서 있지 못해요. 자세를 잡아줄 제어기가 아직 없거든요
