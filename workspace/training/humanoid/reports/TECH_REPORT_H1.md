## 1. 목표

H1이 평지와 요철·경사 지형에서 **넘어지지 않고**, 전진·좌우·회전 명령을 **지시한 속도대로**
추종하도록 학습한다.

설계 우선순위는 예선 시나리오 가중에서 직접 유도했다.

| 시나리오 | 가중 | 명령 성격 |
|---|---:|---|
| H1 제자리 균형 | 0.15 | zero-command |
| H2 전진 | 0.20 | 선속도 |
| H3 좌우 | 0.10 | 선속도 |
| H4 회전 복합 | 0.10 | 선속도 + 각속도 |
| H5 약한 요철 | 0.15 | 선속도 |
| H6 경사 ±10° | 0.15 | 선속도 |
| H7 밀침 회복 | 0.15 | zero-command |

- **명령이 0이 아닌 가중 = 0.70** (H2+H3+H4+H5+H6)
- 그중 **각속도가 걸리는 것은 H4 0.10뿐** — 비제로 명령 가중의 **14.3%**
- **zero-command 가중 = 0.30** (H1+H7) — 여기서는 "정지 속도를 정확히 유지"가 곧 추종이다

→ 따라서 **선속도 추종을 각속도 추종보다 우선한다**는 것이 이 정책의 설계 의도다.
이 의도는 §3 Run 05에서 `track_lin_vel_xy_exp`를 회전 항과 동등한 1.0으로 올린 근거이고,
§6 최종 선정 근거이며, §4에서 실제 행동으로 확인한다.

동시에 **넘어지면 그 시나리오 점수가 0이 된다**(`시나리오 점수 = survival_rate × tracking_score`).
그래서 추종을 올리기 전에 낙상부터 잡는 순서로 실험을 배치했다(§2 → §3).

## 4. H1~H7 평가 결과

**측정 방법과 그 한계를 먼저 밝힌다.**

- 각 시나리오는 `play.py`로 **1000 step(= `episode_length_s` 20.0 ÷ `dt` 0.02 = 1 에피소드)**
  분량의 1920×1080 / 50 fps 영상을 남겼다.
- `play.py`는 성능 수치를 한 줄도 출력하지 않는다(설정 표와 로딩 경로만 출력). 따라서
  **시나리오별 판정의 증거는 영상 육안 확인뿐**이다.
- 판정 방법: `ffmpeg`로 40프레임 간격 25장을 5×5 대조지로 만들어 자세 붕괴 여부를 확인했다.
- ⚠️ **그러므로 아래 "생존" 열은 `survival_rate`가 아니다.** 추적 환경 1개 · 에피소드 1회 ·
  25프레임 표본에서 **낙상이 관찰되지 않았다**는 뜻이다. 공식 평가의 다회 rollout 비율과 다르다.
- ⚠️ **"추종 오차" 열도 시나리오별로 격리 측정한 값이 아니다.** 학습 지형 분포 전체에 대한
  집계값(iter 2999)이므로 참고용으로 병기한다. 시나리오별 정량 추종은 미측정이다.

> 평지는 균일면, H6는 각진 경사면이 나타나 override가 반영됐음을 확인했다.

## 6. 최종 정책 선정 근거

- **최종 선택 정책:** `train_260829-05` (iter 2738 체크포인트)

- **선택 이유:** 낙상 축에서 Run 04와 Run 05는 동률이다(0.3073 vs 0.3020, 영상 4종에서도 동률).
  따라서 추종 축이 판정한다. §1의 가중 분석대로 비제로 명령 가중 0.70 중 각속도는 14.3%뿐이므로,
  직진 오차 -21.2% / 회전 오차 +47.9%의 교환은 **가중 환산에서 Run 05가 앞선다**
  (H4를 전부 각속도로 잡아도 +7.93). 역전에 필요한 각속도 지분 30.7% 대 실제 14.3%로
  경계 판정이 아니다. 여기에 `track_lin_vel_xy_exp`는 **명령이 0일 때도 "정지 속도 추종"으로
  작동**하므로 zero-command 가중 0.30(H1·H7)에서도 Run 05에 유리하게 작용한다 —
  위 계산은 이 몫을 빼고 한 것이라 Run 05에게 보수적이다.

- **다른 후보보다 우수한 H1~H7 항목:** H2(0.20) · H3(0.10) · H5(0.15) · H6(0.15) —
  직진 계열 합계 **0.60**. 집계 `error_vel_xy` 기준 Run 04 대비 21.2% 개선.

- **남아 있는 한계:**
  1. **H4 회전 추종이 이 정책의 명확한 약점이다.** 집계 `error_vel_yaw` 0.9290은 Run 04(0.6230)
     보다 나쁘다. 가중이 0.10으로 작아 총합에서는 이기지만, **H4 단독 점수는 Run 04가 높을 것**이다.
  2. **3000 iter는 수렴점이 아니다.** `error_vel_yaw`가 마지막 1000 iter에서 여전히
     **-0.106/1k**로 내려가는 중이고(Run 04는 -0.0498/1k), 지형 커리큘럼은 **5.56 / 최대 9.0**
     으로 포화하지 않았다. 즉 위 1번의 회전 열위가 **보상 설정의 최종 성격인지 학습 중간 상태인지
     아직 구분되지 않는다.** 최종 제출본은 10000~15000 iter로 학습해 이를 확정한다.
  3. **낙상률 30.2%는 절대 수준에서 높다.** 4개 run · 3개 노브 동안 움직이지 않았다.
