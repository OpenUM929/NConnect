09. 키보드로 조작하기

키보드로 로봇을 직접 조종하면 어디까지 움직일 수 있을까요? 키를 하나씩 눌러보며 확인해봐요. 그리고 챕터2에서 로봇이 얻은 감각을 한자리에 모아 정리해요.

①

생각 열기

완전 자율이 아니라 사람이 직접 조종하는 방식은 왜 아직도 중요할까요? 그런 로봇이 어디에 있는지 함께 떠올려봐요.

사람이 멀리서 조종하는 로봇

저 멀리 화성, 깊은 바닷속, 정밀한 수술대 위. 사람이 직접 가기 어려운 곳에서도 로봇은 일해요. 대신 사람이 멀리서 조종하죠. 이렇게 사람이 원격으로 로봇을 움직이는 방식을 텔레오퍼레이션(Teleoperation)이라고 해요. 앞의 "텔레(tele)"가 "멀리"라는 뜻이죠. 완전 자율이 아직 어려운 일이 많아, 지금도 많은 로봇이 이렇게 움직여요. 줄여서 텔레옵이라고 불러요.

화성 탐사 로버

지구에서 조종

통신이 지연돼도 사람이 경로를 정하는 편이 더 안전해요.

예측 불가능한 환경에서는 사람의 판단이 중요해요.

로봇을 배울 때도 텔레옵은 중간 단계예요. 완전 자율 전에 "사람이 키를 누르면 로봇이 움직이는" 단순한 방식으로 시스템을 먼저 시험해볼 수 있어요.

③

개념 만나기

강화학습 정책(로봇이 스스로 익힌 행동 규칙)이 아직 없다면, 로봇을 움직일 방법은 뭐가 있을까요? 세 가지를 나란히 비교해봐요.

움직이게 하는 세 가지 접근

같은 "움직여"라는 명령도, 어느 수준으로 내리느냐에 따라 난이도가 확 달라져요. 방법 세 가지를 나란히 놓고 봐요.

방법내용한계
① 관절 각도 직접 제어키 한 번에 관절 하나만 조금 움직이는 방식걷기는 사실상 불가능
② Position 제어 + 자세 변경"기본 자세 유지"를 키 입력으로 변형뻣뻣하지만 어느 정도 반응
③ 강화학습 정책 + 키 입력키 → 속도 벡터 → 학습된 정책 → 관절다음 챕터 학습이 끝나야 가능
이번엔 ②를 직접 해봐요. Position 제어는 5강에서 만난 그 방식이에요. 목표 각도만 알려주면 제어기가 힘을 계산해 그쪽으로 움직여줘요. ③은 다음 챕터를 지난 뒤에 만나요.

키 하나와 관절 열아홉 개 사이

직접 해보기

Isaac Sim의 키보드 이벤트를 구독해, 지금 어떤 키가 눌려 있는지 코드가 실시간으로 알게 만들어요. 그 키를 관절 목표 각도로 연결해 로봇을 직접 조종해봐요.

키보드 입력 구독 클래스

여기서 구독은 "이런 일이 생기면 나에게 알려달라"고 미리 등록해두는 걸 말해요. 채널을 구독해두면 새 영상이 올라올 때 알림이 오는 것과 같아요.carb.input과 omni.appwindow, 이 두 모듈이 Isaac Sim의 키보드를 코드에 연결해줘요. 키 이벤트를 구독해두면, 키를 누르고 뗄 때마다 그 사실이 코드로 전해져요.

집합이 비어 있어요. 매 스텝 is_pressed가 False를 돌려주니 각도는 그대로예요.

집합을 건드리는 건 누른 순간과 뗀 순간 둘뿐이에요. 유지되는 이벤트에서도 빼버리면 키를 꾹 누르고 있는데 조종이 뚝뚝 끊겨요. 그리고 집합이라서 두 키가 나란히 담겨요.

전체 코드와 실행 결과

핵심을 포함한 전체 코드예요. 그대로 복사해 실행한 뒤 W와 S를 눌러보고, 실행 결과 탭에서 콘솔 출력을 확인해보세요.

자주 마주치는 문제

실습 중 가장 많이 마주치는 네 가지예요. 클릭하면 원인과 해결법이 펼쳐져요.

키를 눌러도 안 움직여요 ›
원인: 키보드 입력은 창에 포커스가 있는 쪽으로 들어가요. Script Editor에 커서가 남아 있으면 그쪽이 키를 먹어요.
해결: 뷰포트를 한 번 클릭해 포커스를 옮기고 다시 눌러요.
ValueError 관절 이름을 못 찾아요 ›
원인: dof_names.index("left_shoulder_pitch")가 목록에 없는 이름을 찾으면 ValueError가 나요. 관절 이름은 로봇마다 달라서, H1은 _joint가 붙지 않고 Go2는 붙어요.
해결: print(h1.dof_names)로 실제 이름을 먼저 확인하고 그 이름을 그대로 써요.
팔이 일정 각도에서 멈춰요 ›
원인: np.clip(angle, -0.4, 1.4)이 목표 각도를 그 사이로 묶어둬요. 키를 계속 눌러도 1.4를 넘지 않아요.
해결: 관절이 실제로 갈 수 있는 범위 안에서 이 숫자를 넓혀요. 한계는 h1.dof_properties로 확인해요.
다시 돌리면 키가 두 번씩 먹혀요 ›
원인: 앞서 만든 키보드 구독이 살아 있는데 새로 구독하면 같은 키를 여러 번 받아요.
해결: Q로 정상 종료해서 teleop.close()까지 실행되게 해요. 이미 꼬였으면 새 스테이지를 열고 다시 시작해요.
키를 누른 만큼 팔 관절이 목표 각도를 따라 움직여요. 그런데 관절 19개 중 우리가 만진 건 2개뿐이죠. 걷기는 그 19개를 매 순간 정교하게 맞춰야 하는데, 사람이 키 몇 개로 해낼 수 있는 일이 아니거든요.

사람이 코딩해야 할 걷기 규칙

그런데 딱 하나, 스스로 걷기가 비어 있죠. 이걸 사람이 코드로 채운다면 어떨까요? 다리 관절을 언제 어떤 각도로 움직일지 하나하나 정해줘야 해요. 상상해봐요.

같은 "앞으로 가" 명령이라도 그 자리를 채우는 방식은 둘이에요. 왼쪽처럼 사람이 규칙으로 짜면 상황마다 규칙을 더해야 해서 경우의 수가 폭발해요. 오른쪽은 로봇이 시도와 넘어짐을 되풀이하며 보상을 따라 요령을 찾아가는 길이에요.

"앞으로 가" 명령 보내보기

그럼 그 자리를 무엇이 채울까요? 로봇에게 명령을 보내고 학습 전과 학습 후를 토글해 비교해보세요. 명령은 같은데 무엇이 달라지는지 한눈에 보여요.

먼저 학습 전 상태에서 명령을 보내보세요. 로봇이 걸을 수 있을까요?
감각은 코딩으로 채우고, 몸 쓰기는 학습으로 채워요. 다음 챕터에선 그 몸 쓰기를 로봇이 스스로 익혀요. 그게 강화학습이에요.

실습 코드와 같아요. add가 누름, discard가 뗌이에요. W와 D를 함께 누르고 있다가 W만 손을 뗐을 때 눌려 있는 키 수는?
내 답개
정답 → 1개. 손을 뗄 때마다 집합에서 빠지니, 이 집합만 보면 지금 어떤 키가 눌려 있는지 알 수 있어요.
1집합은 누른 키를 담아두는 통이에요. 뗀 키는 통에서 빠져나가요.
2W는 넣었다가 뺐어요. 통에 남은 키를 세어보세요.

보통 · 100스텝 뒤의 각도
W를 누른 것과 같게 100스텝 동안 각도를 올리고, 그 값을 도로 바꿔 몇 도인지 확인해봐요
import asyncio
import omni.usd
import omni.kit.app
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.utils.stage import add_reference_to_stage
from isaacsim.core.prims import SingleArticulation
from isaacsim.core.utils.types import ArticulationAction
from isaacsim.storage.native import get_assets_root_path

async def main():
    if World.instance() is not None:
        World.instance().clear_instance()
    omni.usd.get_context().new_stage()
    world = World(stage_units_in_meters=1.0)
    world.scene.add_default_ground_plane()

    assets_root = get_assets_root_path()
    h1_usd = assets_root + "/Isaac/Robots/Unitree/H1/h1.usd"
    add_reference_to_stage(usd_path=h1_usd, prim_path="/World/H1")
    h1 = world.scene.add(SingleArticulation(
        prim_path="/World/H1", name="h1_humanoid",
        position=np.array([0.0, 0.0, 1.05])))

    await world.reset_async()

    l_sh = h1.dof_names.index("left_shoulder_pitch")
    r_sh = h1.dof_names.index("right_shoulder_pitch")
    targets = h1.get_joint_positions().copy()
    angle = 0.0

    for step in range(100):
        angle = float(np.clip(angle + 0.01, -0.4, 1.4))
        targets[l_sh] = angle
        targets[r_sh] = angle
        h1.apply_action(ArticulationAction(joint_positions=targets))
        world.step(render=False)
        await omni.kit.app.get_app().next_update_async()

    print(f"100스텝 뒤 목표 어깨 각도(도) = {np.rad2deg(angle):.0f}")

asyncio.ensure_future(main())
매 스텝 0.01 rad씩 올리고 상한은 1.4 rad예요. 100스텝 뒤 각도를 도로 바꾸면 몇 도일까요?
내 답도
정답 → 57도. (0.01 × 100 = 1.0 rad, 상한 1.4보다 작아 그대로 남아요. 1 rad ≈ 57.3도라 반올림하면 57도)
1한 스텝에 0.01 rad씩 더해지니, 100스텝이면 라디안으로 얼마가 쌓일지 먼저 구해봐요.
2그 값이 상한 1.4를 넘지 않으면 쌓인 값이 그대로 남아요.
35강에서 익힌 도 변환을 그 값에 적용해봐요. np.rad2deg가 같은 일을 해줘요.

range(3600)을 돌며 step % 120 == 0일 때만 한 줄씩 찍어요. 실습 본문과 같은 구조예요. 맨 아래 센 줄 수는?
내 답줄
정답 → 30줄. (0, 120, 240 … 3480 = 3480 ÷ 120 + 1 = 30)
1range(3600)의 첫 값은 0이고, 0도 120으로 나눈 나머지가 0이에요.
20부터 시작해 120씩 건너뛰며 3600 바로 앞까지 세어봐요.

목표 배열에서 실제로 덮어쓰는 칸이 몇 개인지 확인해봐요
import asyncio
import omni.usd
import omni.kit.app
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.utils.stage import add_reference_to_stage
from isaacsim.core.prims import SingleArticulation
from isaacsim.core.utils.types import ArticulationAction
from isaacsim.storage.native import get_assets_root_path

async def main():
    if World.instance() is not None:
        World.instance().clear_instance()
    omni.usd.get_context().new_stage()
    world = World(stage_units_in_meters=1.0)
    world.scene.add_default_ground_plane()

    assets_root = get_assets_root_path()
    h1_usd = assets_root + "/Isaac/Robots/Unitree/H1/h1.usd"
    add_reference_to_stage(usd_path=h1_usd, prim_path="/World/H1")
    h1 = world.scene.add(SingleArticulation(
        prim_path="/World/H1", name="h1_humanoid",
        position=np.array([0.0, 0.0, 1.05])))

    await world.reset_async()

    l_sh = h1.dof_names.index("left_shoulder_pitch")
    r_sh = h1.dof_names.index("right_shoulder_pitch")
    before = h1.get_joint_positions().copy()
    targets = before.copy()

    targets[l_sh] = 0.9
    targets[r_sh] = 0.9
    h1.apply_action(ArticulationAction(joint_positions=targets))
    world.step(render=False)
    await omni.kit.app.get_app().next_update_async()

    changed = int(np.sum(targets != before))
    print(f"전체 관절 수 = {len(targets)}")
    print(f"키로 값을 바꾼 관절 수 = {changed}")

asyncio.ensure_future(main())
목표 배열을 복사해두고, 어깨 관절에만 새 값을 넣었어요. targets != before로 센 바뀐 칸 수는?
내 답개
정답 → 2개. (19칸 중 어깨 2칸만 바뀌었고, 나머지 17칸은 지금 자세를 그대로 지켜요)
1코드에서 대괄호로 값을 넣은 줄이 몇 줄인지 세어봐요.
2나머지 칸은 복사한 값 그대로라 before와 같아요.
