## 0. 문서 작성 시점 고지

**이 문서는 Run 04 학습이 시작된 뒤, 결과가 나오기 전에 작성됐다.** 사전 등록 문서를 실행 전에 작성하지 못한 절차 위반이 있었다. 다만 작성 시점에 Run 04의 학습 지표는 아직 존재하지 않으므로, 아래 §3 판정 기준은 결과를 보고 만든 사후 기준이 아니다. Run 04 결과가 들어온 뒤에는 이 기준을 변경하지 않는다.

## 1. 변경 범위

Run 04의 비교 기준선은 **Run 03이 아니라 Run 02**다.

| 항목 | Run 02 (기준선) | Run 03 (폐기) | Run 04 |
|---|---:|---:|---:|
| `termination_penalty` | -50.0 | -90.0 | **-50.0** (Run 02 값 복귀) |
| `track_ang_vel_z_exp` | 0.5 | 0.5 | **1.0** (변경 변수) |
| 나머지 reward | 동일 | 동일 | 변경하지 않음 |
| seed / environments / iterations | 42 / 4,096 / 3,000 | 42 / 4,096 / 3,000 | 동일 유지 필요 |

### 왜 `-90`에서 `-50`으로 되돌리는가

Run 03(`-90`)은 사전 등록된 §6.3 판정 기준에 따라 **채택하지 않음**으로 판정됐다(`train_260828-03_add.md` §7 참조). 채택하지 않은 값은 기준선이 될 수 없다. `-90`을 유지한 채 `track_ang_vel_z_exp`만 바꾸면 "폐기된 설정 위에서 만든 변경"이 되어, 개선이 나와도 그 값이 Run 02 대비 개선인지 Run 03의 손상을 일부 되돌린 것인지 분리할 수 없다.

`-50`으로 복귀하면 Run 04는 **채택 가능한 최선 설정(Run 02)에 대한 단일 변수 실험**이 된다. `-90`은 되돌리는 것이 아니라 **폐기하는 것**이며, 복귀는 후퇴가 아니라 유효한 기준선으로의 복원이다.

### 변경값 `1.0`의 근거

`track_ang_vel_z_exp = 0.5`는 권장 범위 `0.5 ~ 2.0`의 **하한**이다. Run 02의 마지막 iteration에서 `Episode_Reward/track_ang_vel_z_exp = 0.1584`, `Episode_Reward/track_lin_vel_xy_exp = 0.2972`로, 회전 추종 항의 실제 기여가 직진 추종 항의 약 53% 수준이다. 가중치를 `1.0`으로 올리면 같은 정책 행동에서 회전 항 기여가 약 0.317로 직진 항(0.297)과 같은 크기가 된다.

이는 **"2배로 키운다"가 아니라 "두 추종 항의 절대 기여를 대등하게 맞춘다"** 는 근거다. 2.0으로 한 번에 이동하지 않아, 회전 보상 강화의 효과와 부작용(제자리 회전 보상 해킹 위험)을 분리해 관찰한다.

## 2. 근거와 한계

Run 02와 Run 03 모두에서 `error_vel_yaw`가 baseline(0.2367) 대비 크게 악화됐고(0.9341 → 1.7672), Run 03 영상에서 제자리 좌회전이 관찰됐다(`eval_260828-03_add.md`). `termination_penalty` 축은 Run 02(`-50`) 이후 낙상 감소 효과가 포화했음이 확인됐다(`train_260828-03_add.md` §8).

따라서 회전 추종 자체를 직접 보상하는 축으로 전환한다. 다만 이는 **가설이며 최적값의 증거가 아니다.** yaw 오차 악화의 원인이 회전 보상 부족이 아니라 학습 부족(§5)이라면 이 변경은 효과가 없거나 역효과일 수 있다.
