## 2026-09-20 근거 검증 책임자 실증 후 역할화
- 목표: 결론 유지가 아니라 원자료 → 정의/모집단 → 문서 수식 → 추론의 연결을 검증한다. PM이 먼저 수행하고 성공한 절차만 역할화한다.
- 등급: 조사/개선(로컬 검증기). 학습·보상값·배포 코드·승인 ZIP은 변경하지 않는다.
- 실패 재현: 같은 행 다른 열, 숫자 부분문자열, 중복 행, 누락/오류 열, INFORMATION_RUN의 공통 검사 우회. 올바른 근거/탐색 사양 대조군도 함께 검사한다.
- 수정: CSV 근거는 selector(열→정확값)와 cells(열→정확값)로 유일한 행/셀에 결합한다. 기존 key/value는 역사적 인용이며 검증 근거를 대신하지 못한다. 미실행 사양만 명시적으로 이관하고 원자료를 바꾸지 않는다.
- 상태: RECOMMENDED와 INFORMATION_RUN에 같은 번호·변경범위·분석판독·원장·반대증거 검사를 적용한다. 오래된 실제 부적격 후보는 근거와 함께 명시적 비실행 상태로 재분류하며 상태만 바꿔 통과시키지 않는다.
- 한계: 정확한 셀 연결도 산문의 의미/인과/공식 규정 준수를 증명하지 않는다. 정의·모집단·시간창·원식 적용조건·경쟁가설은 직접 대조한다.
- 완료 기준: 실패 테스트가 수정 전 결함을 검출하고 수정 후 올바른 대조군과 함께 통과; 기존 회귀/정본 검사; 절차를 기존 증거 관리자에 통합(중복 역할 추가 금지). 실제 runtime 등록과 문서 역할을 구분한다.

- 범위: 로컬 상황 인지 시험 채점기와 PM brief 생성기만 고친다. 학습 코드·보상값·서버 패키지는 건드리지 않는다.
- 행동 고정: 기존 정답표는 통과하고, Q01 점수 오답·Q03 현행 병목 오답·Q12 승인 불필요 주장은 실패해야 한다. 이는 일부 구조화 사실 검사이지 자유 서술의 의미 완전 검증이 아니다.
- 원장 정합성: PM 결정 대기는 결함 대장뿐 아니라 `go2_open_decisions.py`의 `OPEN` 결정에서 읽고, 출처를 구분한다.
- 순서: 실패 회귀 테스트 → 생성기 최소 수정 → 보고서 재생성 → 표적 테스트와 diff 확인.
