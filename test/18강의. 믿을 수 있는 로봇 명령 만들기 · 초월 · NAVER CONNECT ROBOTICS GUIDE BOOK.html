18. 믿을 수 있는 로봇 명령 만들기

LLM은 사람처럼 말로 답하지만, 로봇은 그 말을 바로 알아들을 수 없어요.오늘은 로봇이 알아들을 수 있는 구조인 JSON이라는 약속으로, 그 답을 믿을 수 있게 만들어요.

①

생각 열기

수다스러운 LLM

LLM은 원래 사람의 자연어 대화를 처리하도록 개발된 모델이에요. 그래서 무엇을 물어도 사람처럼 친절하게 설명하려는 성질이 있어요.숫자만 달라고 해도 앞에 "네! 요청하신 명령입니다:"를 붙이거나, 뒤에 "안전 운행하세요!"라고 덧붙이곤 하죠.그런데 로봇은 달라요. 0.1초 단위로 움직임을 갱신하는 로봇에게 필요한 건 설명이 아니라, vx, vy, vyaw = 0.4, 0.0, 0.3처럼 형식이 정해진 구조화된 데이터예요.사람에게는 친절한 한마디지만, 오직 '숫자 데이터'만 받아 적어야 하는 로봇 코드에는 방해물(오류)이 될 뿐이에요.

그래서 필요한 건 부탁이 아니라 계약(contract)이에요. "너는 반드시 이 형식으로만 답한다"는 약속이요. 사람의 말과 기계의 숫자 사이, 그 계약의 표준 형식이 JSON이에요.

PART 1 JSON 이해하기

왜 하필 JSON일까

사람의 글은 같은 뜻도 모양이 제각각이에요. "0.4로 전진"이라 쓰든 "전진 속도는 0.4"라 쓰든 사람은 다 알아듣죠.하지만 코드는 달라요. 모양이 흔들리지 않는 구조화된 데이터라야 값을 꺼낼 수 있어요.그래서 기계끼리 데이터를 주고받을 땐 규격이 필요해요. 그 표준이 JSON이에요.사람도 읽을 수 있으면서, 파이썬은 json.loads() 한 줄로 안정적으로 읽어요.

JSON 첫 만남, 속도 벡터 하나
줄을 누르면 해설
{ "vx": 0.4, "vy": 0.0, "yaw": 0.3}
// 표시된 줄을 클릭하면 해설
밑줄 친 줄을 클릭하면 무슨 일을 하는지 짚어줄게요.

세 숫자의 단위, 그리고 어느 정도인지

vx·vy는 m/s(초당 미터), yaw는 rad/s(초당 라디안)예요.왜 「초당」일까요? 로봇 제어는 아주 짧은 주기로 "지금 이 순간의 속도"를 계속 새로 건네주는 방식이거든요. 시속(km/h)은 자동차를 볼 때 편한 단위지만, 이렇게 촘촘히 갱신하는 제어에는 초 단위가 자연스러워요.회전은 왜 도(°)가 아니라 라디안일까요? 라디안으로 적으면 돌아간 각도에 반지름만 곱해 실제로 움직인 거리가 바로 나와요. 도(°)를 쓰면 계산마다 변환을 끼워야 하죠. 그래서 물리 엔진도 정책도 라디안으로 계산하고, 우리도 같은 단위로 건네요. 참고로 1rad는 약 57°, 한 바퀴(360°)는 2π, 곧 약 6.28rad예요.그럼 0.4와 0.3은 몸으로 어느 정도일까요? 아래에서 값을 직접 움직여보세요.

vx 앞뒤로 가는 속도 0.4m/s

1초에 0.4m — 시속 1.4km예요. 사람 보통 걸음(약 1.2m/s)의 33% 정도라, 10m를 가려면 25초가 걸려요.

yaw 제자리에서 도는 속도 0.3rad/s

1초에 약 17° — 한 바퀴(360°) 도는 데 약 21초예요. 시계 초침(초당 6°)보다 2.9배 빨라요.

import json text = '{"vx": 0.4, "vy": 0.0, "yaw": 0.3}'cmd = json.loads(text) print(cmd["vx"])
// 표시된 줄을 클릭하면 해설
밑줄 친 줄을 클릭하면 무슨 일을 하는지 짚어줄게요.
0.4
0.4가 출력돼요. 글자 뭉치였던 text가 json.loads() 한 줄로, 이름표로 값을 꺼내 쓰는 데이터가 됐어요.
정리하면 LLM의 "말"과 로봇의 "숫자" 사이에 JSON이라는 규격을 끼운다예요.
PART 2 좋은 지시문 쓰기

좋은 프롬프트의 4요소

LLM에게 일을 시키는 글(프롬프트)은 네 요소로 구성해요.

LLM에게 맡길 일을 정해줘요. 여기선 "사람 말을 로봇 속도(vx·vy·yaw)로 바꾸는 변환기"라고 역할을 분명히 정해요.

system과 user의 분리

우리 코드는 LLM을 API로 불러 써요. API는 프로그램이 다른 프로그램에게 일을 시키는 창구예요.LLM 서버에 "이 메시지에 답해줘"라고 요청을 보내면, 답이 돌아오는 구조예요.이 대화형 LLM API에는 메시지 자리가 두 개 있어요. 규칙을 system에 한 번 넣어두면, user에는 상황만 갱신해서 보내면 돼요. 역할이 흔들리지 않고 코드도 깔끔해져요.

자리담는 것갱신
system변하지 않는 역할·규칙·출력 형식한 번 정의 후 고정
user지금 이 순간의 상황·명령매 호출마다 갱신
실제로는 이렇게 써요, system + user
줄을 누르면 해설
messages = [ {"role": "system", "content": "너는 사람 말을 로봇 속도로 바꾸는 변환기다. " '반드시 JSON으로만 답한다: {"vx":.., "vy":.., "yaw":..}'},  {"role": "user", "content": "앞으로 천천히 가면서 살짝 왼쪽으로 틀어"},]resp = call_llm(messages)
// 표시된 줄을 클릭하면 해설
밑줄 친 줄을 클릭하면 무슨 일을 하는지 짚어줄게요.

LLM이 잘 알아듣게 쓰는 팁

4요소 중 손이 가장 많이 가는 건 상태예요. 우리가 만든 구조에서 LLM은 세상을 직접 보지 못해요. 카메라와 센서를 LLM에 바로 연결하지 않았으니, 아는 건 오직 우리가 글과 숫자로 적어 보낸 것뿐이에요.그래서 같은 LLM이라도 어떻게 적어 주느냐에 따라 판단이 확 달라져요. 잘 적는 팁 두 가지를 순서대로 볼게요.

▶ 참고 카메라를 LLM에 바로 연결하면 안 되나요?
연결할 수 있어요. 글과 이미지를 함께 이해하는 모델을 VLM(Vision-Language Model, 시각 언어 모델)이라고 하고, 요즘 상용 모델은 대부분 사진을 같이 받아요. 로봇 연구에서도 카메라 영상을 그대로 넣는 방식을 활발히 쓰고 있어요.그런데 이번 대회처럼 로봇을 실시간으로 움직여야 할 때는 그렇게 하지 않아요. 이유가 세 가지예요.· 느려요. LLM은 한 번 답하는 데 몇 초가 걸려요. 0.1초마다 갱신되는 제어 루프에 영상을 매 장면 넣고 기다릴 수는 없어요.· 이미 정확한 숫자가 있어요. 시뮬레이터와 센서가 위치·거리·각도를 이미 계산해 둬요. 그걸 그림으로 바꿔 다시 짐작하게 하는 건 손해죠.· 판단의 근거가 보여요. 우리가 적어 보낸 숫자가 곧 근거라서, 답이 이상할 때 무엇이 빠졌는지 되짚을 수 있어요.그래서 실제 로봇은 카메라 → (인식) → 숫자로 요약한 상태 → LLM 순서로 이어 붙여요. 보는 일은 빠른 인식 모델이 맡고, LLM은 요약된 숫자를 받아 판단만 하는 거예요. 17강에서 본 대뇌·소뇌 분업과 같은 이야기죠.

팁 1 · 상태는 기준과 함께, 숫자로

보는 일은 인식이 맡고 우리는 그 결과를 적어 보내는 쪽이니, 센서가 이미 계산해 둔 값을 숫자 그대로 옮기는 게 가장 정확해요. "오른쪽 저기"는 모델마다 다르게 읽지만, 숫자는 누가 읽어도 같아요.대신 숫자에는 기준을 꼭 같이 적어요. "3.2m"만 적으면 어디서부터 3.2m인지 알 수 없으니까요. 그래서 늘 로봇을 기준으로 적어요. 목표물이 로봇에서 몇 m 떨어져 있고, 로봇 정면을 0으로 두었을 때 어느 쪽으로 얼마나 틀어져 있는지를요. 방향의 부호는 17강 규약 그대로예요. 왼쪽이 +, 오른쪽이 −예요.또 전체 로그를 다 던지면 LLM도 길을 잃으니, 판단에 필요한 것만 보내요.

항목좋은 전달나쁜 전달
목표물로봇에서 3.2m, 정면 기준 왼쪽으로 0.4 rad(약 23°)저~기 오른쪽 어딘가에 있음
장애물로봇 정면에서 1.8m 앞앞에 뭔가 있는 것 같기도
남은 시간42초(시간 정보 없음)

팁 2 · 예시로 가르치기 (few-shot)

system prompt에 모범 예시 2~3개를 넣어두면, 응답의 들쭉날쭉함이 눈에 띄게 줄어요.보통 2~5개면 충분해요. 더 늘려도 좋아지는 폭은 작고, 지시문만 길어져 답이 느려져요.

실제로는 이렇게 써요, few-shot 예시
줄을 누르면 해설
SYSTEM_PROMPT = """너는 사람 말을 로봇 속도로 바꾸는 변환기다.반드시 JSON만 출력한다: {"vx":.., "vy":.., "yaw":..} 입력: 앞으로 천천히출력: {"vx": 0.3, "vy": 0, "yaw": 0} 입력: 제자리에서 왼쪽으로 돌아출력: {"vx": 0, "vy": 0, "yaw": 0.5} 입력: 살짝 뒤로 가출력: {"vx": -0.2, "vy": 0, "yaw": 0}"""
// 표시된 줄을 클릭하면 해설

PART 3 형식 보장

부탁하지 말고 강제하기, 함수 호출

좋은 지시문을 써도, LLM이 그 형식을 안 지키면 소용없죠. 이번엔 형식을 아예 강제해요.지금까지 우리가 한 건 "제발 JSON으로만 답해줘"라고 단호히 부탁하고, 어기면 파서로 도려내는 방식이었어요. 잘 통하지만 가끔은 어겨요.Claude·GPT·Gemini 같은 상용 API에는 한 수 위의 장치가 있어요. 원하는 형식(스키마)을 미리 등록해두면 모델이 그 형식에 맞게 출력해줘요. 이걸 함수 호출(function calling), 또는 구조화 출력(structured output)이라고 해요.

프롬프트로 부탁 (우리 방식)스키마로 강제 (함수 호출)
형식 보장대체로. 가끔 어김지켜져요
파서 안전망필요 (extract_json)거의 불필요
쓰는 곳로컬·임베디드 등 어디서나상용 API(클라우드)
배우는 값원리를 손으로 익힘실무에서 가장 빠르고 안전
구조화 출력, 스키마로 형식 강제하기
줄을 누르면 해설
tools = [{ "type": "function", "function": { "name": "set_velocity", "description": "로봇의 목표 속도를 설정한다", "parameters": { "type": "object", "properties": { "velocity_x": {"type": "number", "minimum": -1.0, "maximum": 1.0}, "velocity_y": {"type": "number", "minimum": -0.5, "maximum": 0.5}, "velocity_yaw": {"type": "number", "minimum": -1.0, "maximum": 1.0}, "reason": {"type": "string"}, }, "required": ["velocity_x", "velocity_y", "velocity_yaw"], }, },}] resp = requests.post(LLM_URL, json={ "model": MODEL, "messages": [...], "tools": tools,})call = resp.json()["choices"][0]["message"]["tool_calls"][0]cmd = json.loads(call["function"]["arguments"])
// 표시된 줄을 클릭하면 해설
밑줄 친 줄을 클릭하면 무슨 일을 하는지 짚어줄게요.
▶ 참고 스키마가 막아주지 않는 것들
스키마는 답의 모양을 지켜줘요. 하지만 지켜주지 못하는 자리가 남아 있어요.· 값의 범위는 안 막아요. minimum·maximum은 모델에게 주는 힌트일 뿐이에요. velocity_x: 5.0이 와도 에러 없이 통과해요. 에러가 안 나는 대신 로봇이 위험하게 움직이니, 오히려 더 무서운 실패예요.· 모양이 맞아도 값이 틀릴 수 있어요. "뒤로 가"라고 했는데 velocity_x: 0.5(전진)를 채워 넣을 수 있어요. 형식 강제는 옳음까지 보장하지 않아요.· 함수를 아예 안 부를 수 있어요. 모델이 말로 답해버리면 tool_calls가 없어서 KeyError나 IndexError: list index out of range가 떠요.· 답이 길어 잘리면 인자도 잘려요. 응답 길이 제한에 걸려 중간에 끊기면, 미완성 JSON이 와서 JSONDecodeError가 나요.· 지원 여부가 제각각이에요. 모델과 API 버전에 따라 이 기능이 없거나, 옵션을 켜야 구조·타입까지 지켜주는 곳도 있어요.그래서 형식을 강제하더라도 안전망은 남겨둬요. 값을 자르는 clamp, 답이 없을 때의 대비, 마지막에는 정지. 다음 파트에서 그 안전망을 만들어요.
그런데 이 기능은 모든 LLM에 있는 게 아니에요. 우리 실습처럼 내 컴퓨터에서 돌리는 LLM에는 없을 때가 많아요.그래서 두 가지를 다 알아두면 좋아요. 강제할 수 있으면 강제하고, 안 되면 앞에서 배운 대로 직접 부탁하고 검사하면 돼요.
PART 4 못 믿을 때의 안전망

값도 한 번 더, 검증과 clamp

출력 형식까지 보장했어요. 그래도 LLM은 느려지거나, 엉뚱한 값을 낼 수 있어요.출력 형식이 JSON이어도 값 자체는 안전하지 않을 수 있어요. "전속력으로!"라고 하면 velocity_x: 5.0처럼 너무 큰 값을 내놓는 식이죠. 보행 정책은 학습 때 본 적 없는 속도를 받으면 이상하게 걷거나 휘청여요.그래서 규칙은 하나예요. LLM의 출력은 신뢰하되, 항상 확인한다. 범위 밖 값은 잘라내는(clamp) 한 겹을 둬요.

초록 띠는 로봇이 안전하게 받을 수 있는 범위예요. LLM이 보낸 속도(주황 손잡이)를 아무리 멀리 끌어도, 로봇이 실제로 받는 값(청록)은 초록 끝에서 멈춰요.
즉 로봇은 늘 안전 범위 안에서만 움직여요.

🖐 주황 손잡이를 좌우로 드래그해보세요 (LLM이 보낸 전진 속도)
로봇이 받음 1.0
LLM 출력 1.6
초록 = 안전 범위 (−1.0 ~ +1.0)✂ 범위 밖! 잘렸어요
초록이 정책이 학습한 안전 범위예요. LLM이 그 밖의 값을 줘도 clamp가 잘라서 보내니, 소뇌(정책)에는 늘 안전한 값만 도달해요.
대뇌가 어떤 엉뚱한 값을 내도 소뇌에는 안전한 값만 도달하게. 이 한 겹이 실제 로봇 시스템의 기본기예요.

침묵과 거짓, LLM 안전망

clamp로 "이상한 값"은 걸러냈어요. 그런데 문제가 되는 경우가 두 가지 더 있어요.① LLM이 답변을 아무것도 주지 않을 경우. 서버가 느리거나 연결이 끊기면, 2초면 올 답이 30초가 지나도 안 와요.② LLM이 없는 것을 지어낼 경우. "치울 큐브는 1·3·7번이야"라고 알려줬는데도 "5번 큐브로 가겠습니다"라고 답하는 식이에요. 코드는 있지도 않은 5번을 찾다가 IndexError로 멈추거나, 더 나쁘면 로봇을 엉뚱한 자리로 보내요. 이렇게 그럴듯하지만 사실이 아닌 답을 지어내는 것을 환각이라고 해요.사람이라면 기다리거나 다시 물으면 되지만, 로봇은 그 사이에도 계속 움직여요. 그래서 미리 대비해 둬야 해요.아래 로봇에서 정상일 때와, 두 경우가 어긋날 때(침묵·거짓)를 직접 눌러봐요.

LLM이 제때 답하고, 고른 목표 3이 실제 목록 {1,3,7} 안에 있어요. 검증 통과 → 로봇이 실행해요.

그냥 맡기면데이터에 묶으면 (그라운딩)
LLM에게 주는 것"알아서 목표를 골라""목표는 1·3·7번뿐. 이 안에서만 골라"
LLM의 답없는 "5번"을 지어내기도반드시 준 목록 안에서
그다음검증 없으면 엉뚱한 데로답이 목록에 있는지 한 번 더 확인

JSONDecodeError JSON 파싱이 깨져요 ›
원인: LLM이 JSON 밖에 텍스트를 붙였어요.
해결: extract_json() 안전망을 적용하고, system prompt의 형식 문구를 더 단호하게 다듬어요.
같은 명령인데 매번 값이 달라요 ›
원인: temperature가 높거나 예시가 없어요.
해결: temperature를 0.0~0.1로 내리고, few-shot 예시를 2~3개 추가해요.
reason이 영어로 나와요 ›
원인: 출력 언어를 지정하지 않았어요.
해결: system prompt에 "reason은 한국어로"를 명시해요.

코드 실습하기

실습 2에서 만든 안전망 함수들을 다시 꺼내, 값이 어떻게 바뀌는지 눈으로 확인해요.각 문항은 짧은 독립 코드예요. 위 실습 파일을 고치는 게 아니라, 코드 버튼으로 코드를 보고 복사해 실행하면 답이 출력돼요. 그 값을 적으면 돼요. 세 문항 모두 LLM을 부르지 않는 순수 파이썬이에요.

🥚
기본 · 범위 밖 값 잘라내기
실습 2 값 검증 탭에서 만든 clamp예요. LLM이 "전속력!"이라며 범위(−1.0~1.0)를 넘는 값을 냈을 때 어떻게 되는지 봐요.
def clamp(v, lo, hi):
    return max(lo, min(hi, float(v)))

print(clamp(1.8, -1.0, 1.0))
출력된 값을 입력해보세요.
내 답
정답 → 1.0
1min(hi, v)로 위를, max(lo, ...)로 아래를 막아요.
21.8은 위쪽 경계로 잘려요.
🐣
보통 · 옆걸음만 범위가 좁아요
같은 탭의 sanitize예요. 세 속도를 각자의 범위로 자르는데, 옆으로 미는 velocity_y만 −0.5~0.5로 좁아요.
def clamp(v, lo, hi):
    return max(lo, min(hi, float(v)))

def sanitize(cmd):
    return {
        "velocity_x":   clamp(cmd.get("velocity_x", 0.0),  -1.0, 1.0),
        "velocity_y":   clamp(cmd.get("velocity_y", 0.0),  -0.5, 0.5),
        "velocity_yaw": clamp(cmd.get("velocity_yaw", 0.0), -1.0, 1.0),
    }

out = sanitize({"velocity_x": 0.3, "velocity_y": 0.9, "velocity_yaw": 2.0})
print(out["velocity_y"])
출력된 velocity_y 값을 입력해보세요.
내 답
정답 → 0.5
1velocity_y의 범위는 −0.5~0.5예요.
20.9는 위쪽 경계로 잘려요.
🐥
도전 · 잡담 속에서 JSON만 건지기
실습 2 파서 안전망 탭의 extract_json이에요. 앞뒤 잡담이 붙어도 중괄호 안 JSON만 도려내요. (정규식은 지금 몰라도 괜찮아요)
import json, re

def extract_json(text):
    m = re.search(r"\{.*\}", text, re.DOTALL)
    if m is None:
        raise ValueError("JSON 없음")
    return json.loads(m.group(0))

messy = '좋아요! {"velocity_x": 0.6, "velocity_y": -0.3, "velocity_yaw": 0.0} 이렇게 갈게요.'
cmd = extract_json(messy)
print(cmd["velocity_y"])
건져낸 명령의 velocity_y 값을 입력해보세요.
내 답
정답 → -0.3
1정규식이 첫 {부터 마지막 }까지를 잡아요.
2그 조각만 json.loads로 딕셔너리로 바꿔 키로 값을 꺼내요.
🐔
심화 · few-shot 전후 비교
예시 3개를 넣기 전/후로 같은 명령을 5번씩 보내 흔들림을 비교해봐요. (라이브 LLM이라 정해진 정답은 없어요)
1"앞으로 적당히 빠르게"처럼 살짝 애매한 명령이 비교에 좋아요.
2전/후 각각 5번의 velocity_x 값을 나란히 적어요.
3값의 퍼짐이 줄었는지 숫자로 확인해보세요. 프롬프트 엔지니어링의 힘이에요.
🐓
탐구 · 금지 명령 방어
"벽에 부딪혀봐", "최고 속도의 두 배로" 같은 무리한 명령에 어떻게 반응하는지 확인해봐요.
1무리한 명령 5개를 만들어 변환기에 넣어요.
2LLM이 스스로 거절하는지, 아니면 큰 값을 내놓는지 관찰해요.
3어느 쪽이든 clamp가 마지막 방어선으로 작동하는지 검증하세요.

18강 한눈에 정리

  • 로봇과 LLM 사이의 계약 = JSON. 부탁이 아니라 약속이에요
  • 프롬프트 4요소는 역할·상태·목표·형식. 고정은 system, 가변은 user에 둬요
  • LLM이 아는 세상은 우리가 적어 보낸 글이 전부. 상태는 로봇 기준의 숫자로 적어 보내요
  • 형식은 부탁보다 강제. 강제가 안 되면 파서(extract_json)로 JSON만 건져요
  • 신뢰하되 검증. clamp가 범위 밖 값을 잘라 소뇌를 지켜요
  • 환각은 그라운딩으로. 실제 목록에 묶고, 모든 시도가 실패하면 정지예요
