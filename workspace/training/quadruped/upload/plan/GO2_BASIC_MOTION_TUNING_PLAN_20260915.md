## 1. 결론

**A017에서 `feet_air_time` 한 항만 바꾼 두 회차를 돌린다.** G-A031은 0.2→0.01(Isaac Lab Go2 험지 값), G-A032는 0.2→0.1(중간값)이다. 표적은 평지가 아닌 곳의 기본 보행(험지 전진·20° 오르막·DR)이다.

선정 이유:
1. **외부 기준(§3).** A017이 Isaac Lab Go2 험지 설정과 다른 항은 둘뿐이다: `track` 1.4(IL 1.5)와 `feet_air_time` 0.2(IL 0.01, 20배). Isaac Lab은 0.25를 **평지 설정에서만** 쓰고 험지 설정은 0.01이다. A017은 "험지 env에 평지급 체공 보상"인 셈이다. 0.2는 Pilot-01의 4항 동시 변경에서 왔고 단일변수 근거가 없다.
2. **우리 계측(§2).** A017의 약점은 평지가 아니라 비평지다. 평지는 생존 1.0·추종 ≥ .89인데, 험지·오르막에서는 명령 속도의 절반쯤으로 걷고 **몸 높이 게이트**로 낙상 판정을 받는다. 기울기 낙상은 거의 없다.
3. **용량-반응(§2-3).** `feet_air_time`을 0.2→0.35로 올린 A015는 7 case 모두에서 몸 높이(p10)를 0.1~0.18 m 낮추고 생존이 무너졌다. 체공 보상을 올리면 자세가 낮아지는 방향이 관측됐다. 이번 쌍은 그 반대 방향을 시험한다.

**왜 두 회차인가.** 한 점으로는 방향을 정하지 못한다. A016·A018은 작은 변경(action_rate 20% 완화)에도 1,000 iter 안에서 정지 정책으로 무너졌다. 1,000 iter 레시피가 "걷기/서기" 갈림길 가까이에 있다는 뜻이다. 0.01 한 점이 무너지면 그것이 방향 때문인지 갈림길 때문인지 가를 수 없다. 두 점에 A017(0.2)·A015(0.35)를 더하면 한 축에 네 점이 생긴다. **"튜닝값이 예상과 다르게 행동하면?"에 대한 답은 §6-3의 결과→방향 표를 실행 전에 고정해 둔 것이다.**

기대 가중 이득은 **`미추정`**이다. 보행 기준선에서 이 항을 낮춘 측정이 0건이다.

## 10. 재현 코드 (저장소 루트, 표준 라이브러리, 읽기 전용)

```python
import csv, collections, math
from pathlib import Path
def scan(p, hold=25, grace=0.5):
    rows = collections.defaultdict(list)
    with p.open() as f:
        for r in csv.DictReader(f): rows[r["env_id"]].append(r)
    height_only = tilt = 0; ratio = []
    for rs in rows.values():
        rh = rt = 0; fh = ft = False
        for r in rs:
            if r["terminated"] == "1" and r["term_time_out"] != "1": break
            t = float(r["time_s"]); h = float(r["height_rel"]); c = -float(r["proj_grav_z"])
            cmd = math.hypot(float(r["cmd_vx"]), float(r["cmd_vy"]))
            if t >= 1.0 and cmd > 0.05: ratio.append(float(r["speed_xy"]) / cmd)
            if t < grace: continue
            rh = rh + 1 if h < 0.18 else 0; rt = rt + 1 if c < 0.5 else 0
            fh |= rh >= hold; ft |= rt >= hold
        height_only += fh and not ft; tilt += ft
    return height_only, tilt, sum(ratio) / len(ratio)
base = Path("workspace/_keep/go2_a017_full_suite/evaluation")
for arm in ("a017", "pilot"):
    for seed in (101, 202, 303):
        print(arm, seed, scan(base / arm / "cases" / f"seed_{seed}" / "slope_plus_20" / "steps.csv"))
# 기대: a017 (7,0,.57) (8,0,.53) (4,0,.57) · pilot (0,0,.41) (0,0,.43) (0,0,.37)
```

높이 p10은 각 case `summary.json`의 `height_rel_p10`이다. 학습 로그 항 크기는 `logs/candidate_training.log`의 `Episode_Reward/*` 마지막 100 iter 평균이다.
