05. 관절 움직이기

4강에서 불러온 로봇을 이제 움직여볼 차례예요. 지금 로봇은 스스로 균형을 잡는 능력이 없어서, 가만두면 바닥에 주저앉아요.하지만 로봇의 관절을 하나씩 각도로 조작하면 원하는 자세를 만들 수 있어요. 사람이 직접 손으로 움직이는 대신, 코드로 정확한 관절 각도를 명령해야 하죠. 과연 로봇에게 어떤 값을 정해주어야 할까요? 이번 강에서는 휴머노이드 로봇의 왼팔을 들어 인사하는 동작부터 만들어봐요.

①

생각 열기

축구 선수가 프리킥을 찰 때, "무릎을 몇 도 굽혀야지" 하고 각도를 계산하는 사람은 없어요. 사람은 감각으로 다리를 움직이지만, 로봇은 정해진 각도 값이 들어오지 않으면 발조차 들 수 없어요.

"손 들어"가 안 통하는 로봇

사람은 "손 들어" 하면 곧바로 손을 들어요. 어느 팔인지, 얼마나 올릴지 묻지도 않고요. 로봇도 그럴까요? 버튼을 눌러 살펴봐요.

같은 말에 사람과 로봇이 보이는 다른 반응
사람에게도 로봇에게도 똑같이 말해볼까요?

관절마다 정해주는 목표 각도

로봇에게는 어떤 관절을 몇 도로 움직일지 정해줘야 해요. 코드로 로봇을 움직이기 전에, 아래 슬라이더로 팔과 다리를 하나씩 움직여 감을 잡아봐요.

팔과 다리 관절을 각도로 움직여보기
시점좌우는 보는 사람이 아니라 로봇을 기준으로 불러요. 마주보고 선 그림이라, 화면 왼쪽에 있는 팔이 로봇의 오른팔이에요.
옆에 보이는 숫자가 실제 관절 각도예요. 어깨를 0°에 두면 차렷이고, -90°에 가깝게 정하면 팔이 앞으로 올라가요. 실제 어깨는 뒤로도 164°까지 젖혀지지만, 정면에서 보는 그림이라 여기서는 앞으로 드는 쪽만 움직여요.
슬라이더로 각도를 움직여봤지만, 시뮬레이션에서는 그 각도를 코드에 숫자로 적어 넣어요. 그 방법을 이번 강에서 하나씩 익혀요.

③

개념 만나기

먼저 로봇의 몸이 어떻게 이뤄졌는지 보고, 관절을 코드로 다루는 약속들을 하나씩 배워봐요.

뼈대와 관절의 차이

로봇은 뼈대(Link)와 관절(Joint)의 조합으로 이뤄져 있어요. 우리가 조종하는 건 관절이에요. 뼈대는 단단한 부품이라 구부리거나 펼 수 없어요.

뼈대 (Link)

단단한 부품

위팔, 아래팔, 손바닥처럼 모양이 고정된 부분. 직접 조종할 수 없어요.

관절 (Joint)

모터

뼈대 사이를 연결하는 모터. 이 부분이 회전하면서 로봇이 움직여요.

뼈대 ≠ 관절
뼈대(Link)는 단단한 막대예요. 위쪽은 벽에 고정돼 안 움직여요
관절(Joint)은 이 기어가 돌아요. 움직임의 주인공이에요
관절 각도0°
슬라이더나 버튼으로 관절을 돌려보세요. 위 뼈대는 그대로, 기어가 도는 만큼만 아래 뼈대가 따라 움직여요.

이름으로 접근하는 관절

관절은 이름으로 부르고, 숫자 인덱스는 쓰지 않아요. 이 강의에서 가장 중요한 약속이에요. 인덱스로 접근하면 15번이 어깨일 줄 알고 명령하는 일이 생겨요. 실제로 15번이 엉덩이 관절이면, 팔을 들라고 준 명령에 엉뚱하게 다리가 움직여요.

휴머노이드 로봇 관절 이름 지도
관절이나 이름에 마우스를 올리면 짝이 켜져요. 어깨·고관절은 한 자리에서 3축(pitch·roll·yaw)으로 나뉘어요.
시점좌우는 보는 사람이 아니라 로봇을 기준으로 불러요. 마주보고 선 그림이라, 화면 왼쪽에 있는 팔이 로봇의 오른팔이에요.
다리 10 · 팔 8 · 허리 1 = 총 19개. 실제 이름엔 _joint가 붙지 않아요.
인덱스를 외우지 말고 dof_names에서 이름을 검색하는 습관을 들여보세요. left_shoulder_pitch처럼 이름 자체가 어느 부위인지, 어느 방향으로 도는지까지 알려줘요.

컴퓨터의 각도 단위 라디안

코드에서 각도는 도(°)가 아니라 라디안(radian)으로 다뤄요. 길이를 잴 때 미터가 기본 단위인 것처럼, 회전을 계산할 땐 라디안이 기본이에요. 그래서 numpy와 물리 엔진이 전부 라디안으로 계산해요. 우리는 익숙한 도(°)로 생각한 뒤, 명령할 때만 라디안으로 바꿔 넣으면 돼요.

▶ 심화 왜 컴퓨터는 도(°) 대신 라디안을 쓸까요?
사실 도(°)의 360은 그다지 특별한 이유가 없어요. 옛날 바빌로니아 사람들이 1년을 360일쯤으로 어림잡아 정한 숫자거든요.라디안은 달라요. 반지름과 똑같은 길이만큼 원둘레를 따라갔을 때의 각도가 1 라디안이에요. 그런데 원둘레 전체에는 반지름이 약 6.28번 들어가요. 이 6.28을 2π라고 써요. 그래서 원 한 바퀴가 곧 2π 라디안, 약 6.28 라디안인 거예요. 사람이 정한 360과 달리, 라디안은 이렇게 원의 반지름에서 그대로 나온 값이에요.숫자만 보면 270°가 4.71 라디안보다 읽기 편하죠. 하지만 라디안의 장점은 읽기 쉬움이 아니라 계산이 깔끔해진다는 데 있어요. 원과 회전 공식이 라디안일 땐 군더더기 상수 없이 딱 맞아떨어지거든요. 도로 하면 공식마다 자잘한 상수를 더 붙여야 해요. 그래서 컴퓨터와 물리 엔진은 라디안으로 계산하고, 우리는 도가 더 익숙하니 명령을 넣기 직전에만 라디안으로 바꿔주면 돼요.

관절 회전 한계, Joint Limit

사람의 무릎은 뒤로 꺾이지 않아요. 로봇도 똑같아요. 모든 관절에는 움직임의 최소와 최대 각도가 정해져 있어서, 범위를 넘는 값을 명령해도 시뮬레이터가 관절을 한계까지만 움직여요. 아래에서 무릎 각도를 한계 밖까지 정해보세요.

관절이 더 안 돌아가는 한계 각도
명령: 20°  →  실제: 20°
■ 빨간 구역 = 관절이 갈 수 없는 각도 (초록 = 이동 가능 범위)
다른 관절 범위 · 어깨 pitch ±164° · 고관절 pitch -180°~145° · 허리 ±135°. 실제 값은 h1.dof_properties로 조회해요.
관절 회전 한계는 h1.dof_properties["lower"], ["upper"]로 직접 조회할 수 있어요. 학습 코드를 짤 때는 np.clip(targets, lower, upper)로 한 번 잘라주는 안전장치를 두는 게 좋아요. 이 한 줄이 로봇을 한계 안에서 매끄럽게 움직이게 해줘요.

Position 제어와 Torque 제어

관절에 명령하는 방식은 크게 둘이에요. 목표 각도만 정하는 Position 제어와 힘을 직접 정하는 Torque 제어예요. 이 중 Position 제어는 온도조절기와 닮았어요. 온도조절기에 "24도"만 맞춰두면 히터를 얼마나 세게 돌릴지는 알아서 정하죠. Position 제어도 목표 각도만 주면 PD 제어기가 필요한 힘을 계산해줘요. 그래서 5강에서는 쓰기 쉬운 Position 제어를 써요.

▶ 참고 P, PI, PD, PID는 무엇이 다를까요?
이름의 P, I, D는 영어 단어의 첫 글자예요. 셋 다 목표와 지금의 차이, 곧 오차를 다루는데 그 오차를 쓰는 방식이 달라요.P는 Proportional(비례)의 첫 글자로, 지금 오차가 큰 만큼 비례해서 세게 밀어요. 목표에서 멀면 강하게, 가까우면 약하게요. 오차에 비례한다고 해서 "비례"라고 불러요.I는 Integral(적분)로, 오차가 오래 조금씩 쌓인 양까지 더해, 계속 아슬아슬하게 못 미칠 때 그만큼 메워줘요.D는 Derivative(미분)로, 오차가 줄어드는 속도를 봐요. 너무 빨리 다가가면 미리 힘을 빼 목표를 훅 지나치지 않게 해요.엘리베이터로 비유해볼까요? P는 남은 거리에 비례해 속도를 내요. D는 가까워질수록 미리 감속해 목표를 지나치지 않게 해요. I는 조금씩 쌓인 부족분을 끝까지 채워요.이 셋을 어떻게 묶느냐가 제어기 이름이라 P만 쓰면 P 제어기, P와 I면 PI, P와 D면 PD, 셋 다면 PID예요. 로봇 관절엔 오차에 비례하는 P와 오차가 변하는 속도를 보는 D를 합친 PD 제어기가 흔히 쓰여요.
관절에 명령하는 두 방식
Position 제어
"이 각도까지 가줘"처럼 목표만 정해요
  • 온도조절기처럼 목표만 주면 PD 제어기가 알아서 힘 계산
  • 초보자가 쓰기 가장 쉬워요
4강에서 사용
Torque 제어
"이만큼 힘을 줘"처럼 힘을 직접 정해요
  • 더 정밀하지만 언제 멈출지까지 계산해야 해요
  • 안정화가 까다로워요
진화 챕터(강화학습)
5강 데모는 자세를 바로 지정하고, 챌린지에선 Position 제어로 연습해요. Torque 제어는 진화 챕터의 강화학습에서 만나요. 같은 관절이라도 명령 방식에 따라 코드와 결과가 완전히 달라져요.

직접 해보기

관절 이름을 먼저 출력해보고, 그중 어깨 관절 하나를 골라 로봇이 왼팔을 들게 해봐요.

관절 이름표 뽑기

먼저 휴머노이드 로봇의 모든 관절 이름을 Script Editor에 출력해요. 이 리스트를 메모장에 복사해두면 앞으로 계속 참고할 기준이 돼요.

import omni.usdimport numpy as npfrom isaacsim.core.api import Worldfrom isaacsim.core.utils.stage import add_reference_to_stagefrom isaacsim.core.prims import SingleArticulationfrom isaacsim.storage.native import get_assets_root_pathif World.instance() is not None: World.instance().clear_instance()omni.usd.get_context().new_stage()world = World(stage_units_in_meters=1.0)world.scene.add_default_ground_plane()assets_root = get_assets_root_path()h1_usd = assets_root + "/Isaac/Robots/Unitree/H1/h1.usd"add_reference_to_stage(usd_path=h1_usd, prim_path="/World/H1")h1 = world.scene.add( SingleArticulation( prim_path="/World/H1", name="h1_humanoid", position=np.array([0.0, 0.0, 1.05]) ))world.reset()print(f"\nH1 총 관절: {h1.num_dof}개\n")print("번호 | 관절 이름")print("-" * 50)for i, name in enumerate(h1.dof_names): print(f"{i:3d} | {name}")
// 표시된 줄을 클릭하면 해설
밑줄 친 줄을 클릭하면 무슨 일을 하는지 짚어줄게요.

왼팔 들고 인사하기

관절 이름 중 left_shoulder_pitch를 찾아 -90도(약 -1.57 라디안)를 명령해요. 음수면 어깨가 앞으로, 양수면 뒤로 움직여요. 아직 균형을 잡아주는 제어기가 없어 그냥 두면 로봇이 바닥에 주저앉아요. 그래서 이번엔 set_gravity(0.0)으로 중력을 꺼 로봇을 세워둬요. 그 상태에서 관절 하나의 움직임만 또렷이 봐요. 로봇이 서서 균형 잡는 방법은 진화 챕터에서 배워요.

자주 마주치는 문제

실습 중 가장 많이 마주치는 다섯 가지예요. 클릭하면 원인과 해결법이 펼쳐져요.

await world.reset_async()를 호출하지 않음 ›
원인: 관절 정보가 아직 비어 있어 dof_names.index()나 set_joint_positions가 실패해요.
해결: SingleArticulation 등록 뒤 반드시 await world.reset_async()를 호출해주세요.
main()을 실행하지 않음 ›
원인: async def main()을 정의만 하고 실행하지 않으면 아무 일도 일어나지 않아요.
해결: 코드 맨 끝의 asyncio.ensure_future(main()) 한 줄을 빠뜨리지 마세요.
각도를 도(°) 단위로 그대로 넣음 ›
원인: 시뮬레이터는 모든 각도를 라디안으로 해석해요. 90을 그대로 넣으면 90 라디안(≈ 5157°)이 명령돼서 관절이 한계까지 한 번에 튕겨요.
해결: np.deg2rad(90)으로 바꿔서 넣어주세요.
명령만 하고 스텝을 굴리지 않음 ›
원인: 화면은 시뮬레이션 시간이 한 칸 진행될 때 다시 그려져요. 각도를 넣어도 스텝을 굴리지 않으면 바뀐 자세가 화면에 나타나지 않아요.
해결: world.step(render=False)와 await omni.kit.app.get_app().next_update_async() 두 줄로 스텝을 직접 굴려주세요. Script Editor에서 자유롭게 실험할 땐 ▶ Play로 스텝이 계속 돌게 해두면 편해요.
관절 회전 한계를 넘는 각도를 명령함 ›
원인: 에러는 나지 않고 관절이 한계까지만 움직여요. 그래서 의도한 자세가 조용히 어긋나요.
해결: 자세가 안 나오면 관절 회전 한계부터 확인해봐요. 학습할 때는 한계를 넘지 않도록 보상에 페널티를 주기도 해요.

import asyncio
import omni.usd
import omni.kit.app
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.utils.stage import add_reference_to_stage
from isaacsim.core.prims import SingleArticulation
from isaacsim.storage.native import get_assets_root_path

async def main():
    if World.instance() is not None:
        World.instance().clear_instance()
    omni.usd.get_context().new_stage()
    world = World(stage_units_in_meters=1.0)
    world.scene.add_default_ground_plane()
    world.get_physics_context().set_gravity(0.0)

    assets_root = get_assets_root_path()

    h1 = world.scene.add(SingleArticulation(
        prim_path="/World/H1", name="h1_humanoid",
        position=np.array([0, 0, 1.05])))
    await world.reset_async()

    q = np.zeros(len(h1.dof_names))
    target = np.deg2rad(-90)
    q[h1.dof_names.index("right_shoulder_pitch")] = target
    h1.set_joint_positions(q)
    for _ in range(30):

        await omni.kit.app.get_app().next_update_async()
    print(f"오른팔에 명령한 각도 = {target:.2f} rad")

import asyncio
import omni.usd
import omni.kit.app
import numpy as np
from isaacsim.core.api import World
from isaacsim.core.utils.stage import add_reference_to_stage
from isaacsim.core.prims import SingleArticulation
from isaacsim.storage.native import get_assets_root_path

async def main():
    if World.instance() is not None:
        World.instance().clear_instance()
    omni.usd.get_context().new_stage()
    world = World(stage_units_in_meters=1.0)
    world.scene.add_default_ground_plane()
    world.get_physics_context().set_gravity(0.0)

    assets_root = get_assets_root_path()
    h1_usd = assets_root + "/Isaac/Robots/Unitree/H1/h1.usd"
    add_reference_to_stage(usd_path=h1_usd, prim_path="/World/H1")
    h1 = world.scene.add(SingleArticulation(
        prim_path="/World/H1", name="h1_humanoid",
        position=np.array([0, 0, 1.05])))
    await world.reset_async()

    poses = [np.zeros(len(h1.dof_names)) for _ in range(3)]
    poses[1][h1.dof_names.index("left_shoulder_pitch")]  = np.deg2rad(-90)
    poses[2][h1.dof_names.index("right_shoulder_pitch")] = np.deg2rad(-90)

    steps = 0
    for q in poses:
        h1.set_joint_positions(q)
        for _ in range(60):
            world.step(render=False)
            await omni.kit.app.get_app().next_update_async()
            steps += 1
    print(f"시퀀스 전체 스텝 수 = {steps}")

asyncio.ensure_future(main())

내 답스텝
정답 → 180스텝. (3자세 × 60프레임)
1바깥 for는 자세 3개를 하나씩 꺼내요.
2안쪽 for는 한 자세를 60프레임 유지해요. 바깥 × 안쪽이 전체 스텝이에요.

탐구 · 라디안과 도 왕복
도를 라디안으로 바꿨다가 다시 도로 되돌려, 어떤 값이 나오는지 확인해요
import numpy as np

deg = 90
rad = np.deg2rad(deg)
back = np.rad2deg(rad)
print(f"{deg}도 -> {rad:.2f}rad -> 다시 {back:.0f}도")
90°를 라디안으로 바꿨다가 다시 도로 되돌리면? np.rad2deg(np.deg2rad(90))의 결과는?
내 답도
정답 → 90도. (deg2rad와 rad2deg는 서로 반대)
1np.deg2rad는 도 → 라디안이에요.
2np.rad2deg는 라디안 → 도, 정반대예요. 두 함수를 차례로 거치면?

5강 한눈에 정리

  • 조종 대상은 뼈대가 아니라 관절이에요. 관절의 총 개수가 자유도(DoF)이고, 휴머노이드 로봇은 거의 모두 회전 관절이라 단위가 라디안이에요
  • 관절은 인덱스가 아니라 이름으로 접근해요. 이름은 코드만 봐도 어느 관절인지 분명해서, dof_names에서 찾는 게 안전해요
  • 각도의 단위로 도(°)가 아니라 라디안을 써요. np.deg2rad()로 도를 라디안으로 바꿔 명령하고, np.rad2deg()로 되돌려요
  • world.reset() 이전엔 관절 정보가 비어 있어요. reset 뒤에 dof_names로 관절을 찾아 set_joint_positions(targets)로 각도를 명령해요. 자세는 바로 반영되지만, 스텝이 돌아야 화면에 보여요
  • 제어 방식은 여러 가지지만 5강은 set_joint_positions로 각도를 주는 Position 제어예요. 관절마다 한계가 있어서 np.clip()으로 안전하게 잘라 써요
다음 강 안내

로봇이 움직이기 시작했지만 바닥은 여전히 평평해요. 다음 강에서는 지형(Terrain)을 직접 만들어봐요. 그 지형이 그대로 로봇의 훈련장이 돼요. 까다롭게 만들수록 로봇은 더 강해져요.
