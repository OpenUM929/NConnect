# A058 이후 PC 고정 탐색 + 서버 적응형 튜닝 병행 계획 (2026-10-01)

## 0. 최신 사용자 결정과 목적
사용자 정정: 두 전략은 선택지가 아니라 병행한다. 다른 PC의 기존 탐색이 약5일 걸리는 동안 서버에서 기존 우수 보상 설정들을 모아 적극적으로 튜닝하고, 5일 뒤 PC 결과로 서버 튜닝을 강화한다. 이전 판의 '전략2만 선택/PC 최대4행' 권고는 철회한다.
목표: 계단 등반·진행과 험지 이동·추종 개선, 우회전·밀침 이득 보존. 신규 최적값이나 서버 실행을 이 문서에서 확정하지 않는다. 이는 병행 정책 설계이며 실행 ZIP이 아니다.

## 1. PC 트랙 — 기존 고정 탐색을 유지
- A058 결과를 보존·판독한 뒤 G-A057 미완료 행을 기존 값·순서·학습 조건·사전등록대로 진행하는 것이 이번 병행안이다. 완료 행을 재학습하지 않는다. 원격 프로세스의 실제 상태는 로그로 확인한다.
- 약5일은 사용자가 제시한 계획 기간이다. 인계 기록 약9시간/행×11행은 약99시간이며 회수/오류 복구 등을 포함하면 달라질 수 있다.
- 서버에서 좋아진 설정을 PC sweep 중간에 끼워 넣지 않는다. 고정 기준의 변수별 추세를 끝까지 확보하는 역할이다.
- 기존 완료 결과는 도착할 때마다 공유하며 5일째까지 숨기거나 판독을 미루지 않는다. 단, 결과를 보고 PC의 기존 판정 문턱을 바꾸지 않는다.

## 2. 서버 트랙 — 기존 우수 설정을 조합·개선하는 적응형 튜닝
- PC 종료를 기다리지 않는다. 기존 완료 실험의 목표별 우수 설정을 모아 후보를 만들고, 서버 결과가 다음 실행을 바꾼다.
- 출발 자료는 '임의의 특정값 목록'이 아니라 실제 우수 성과가 관측된 정책의 전체 보상 벡터, 해당 행동 성과, 부작용이다. A043은 계단 우수 사례, A048은 종합/험지/밀침 우수 사례로 검토하되 실제 공통 평가 조건에서 다른 후보들도 비교한다.
- 최적값이라고 부르지 않고 '현재 관측 우수 설정'이라고 부른다. A043/A048이 모두 track1.5인 점 등 공통값은 우선 고정한다. 우수 정책이 같은 변수(lin_vel_z)의 서로 다른 값에서 나왔다는 사실을 무시해 값을 짜깁기하지 않는다.

### 서버 후보 선정 순서
1. 계단, 험지 전진/옆걸음, 우회전, 밀침의 성과별 우수 정책을 동일 평가 범위로 추린다. ≥2단과 이후 진행/추종, 종료/기울기/높이만 판정을 구분한다. 총점만으로 선정하지 않는다.
2. 우수 정책들의 전체 보상 벡터를 비교하여 공통값, 충돌값, 단일변수 비교로 지지된 변경을 구분한다. 설정에 들어 있던 값과 그 값의 효과는 다르다.
3. 각 조합은 '어느 우수 설정에서 출발하고, 어느 다른 우수 사례의 어떤 변경을 가져와, 어떤 약점을 개선할지'를 명시한다. 실패 경로→강좌·배포 예측→기존 반례→조합 이유의 순서를 유지한다.
4. 첫 후보는 기준 설정에서 한 항만 바꿔 비교 가능하게 만든다. 다음에 유망 변경을 더할 때도 직전 후보와 한 항 차이로 만든다. 이미 같은 조건의 A/B 단독 결과가 있으면 조합 A+B를 별도로 검증한다. 좋은 효과의 단순 합산을 가정하지 않는다.
5. 결과가 개선이면 해당 설정을 보존하고 다음 약점으로 이동한다. 목표 개선과 다른 필수 행동 손실이 교환되면 별도 후보로 남기고 무조건 기준으로 승격하지 않는다. 악화면 마지막 유망 설정으로 돌아가 해당 방향을 재검토한다.
6. 단순히 미시험이라서, 중간값이라서, 준비된 ZIP이라서 실행하지 않는다. 알려진 실패 변경을 '공격적'이라는 이유로 되풀이하지 않는다. 후보가 기존 우수 설정에서 나오지 않으면 탐색 가설로 구별한다.

### 운영과 예산
- 서버 실행은 사용자, 후보 선택·번호 있는 패키지 준비·회수 후 판독은 Codex 책임이다. 기존 발행 ZIP·원자료·평가기·사전등록은 보존한다. 보상값 외 배포 학습 코드 수정 없음.
- 5일의 PC 벽시계 시간을 서버100시간으로 해석하지 않는다. 실제 서버 잔여 예산과 TTL을 원장에서 확인해 각 실행의 학습+평가+영상+report 회수 비용을 예약한다. 최대 실행 수는 예산 확인 없이 정하지 않는다.
- 공식 서버 동시 접속 금지 등 기존 규정은 유지한다. PC 탐색/서버 사용의 병행은 그 제한을 우회하는 권한이 아니다.

## 3. 5일 뒤 — 합치는 것은 근거이며, 가중치를 평균내지 않는다
- PC의 고정 기준 단일변수 반응과 서버의 적응형 후보 성과를 나란히 비교한다. PC는 PC 기준, 서버는 서버 기준의 변화량으로 읽으며 절대값을 한 회귀/순위에 무조건 합치지 않는다.
- 양쪽에서 방향이 맞으면 우선순위를 높인다. 그래도 서버 조합에서 같은 효과가 보장되지는 않는다.
- PC에서만 좋아진 변경은 현재 서버 우수 설정 위의 추가 후보로 검증한다. 서버에서만 좋아진 변경은 서버의 관측 이득을 보존하고 PC 반례와 조건 차이를 함께 기록한다.
- 서로 충돌하면 이미 좋은 서버 설정을 즉시 버리거나 PC 결과를 무시하지 않는다. 기준 보상·기기·학습seed·평가 구성 차이 중 확인된 차이와 미분리 요인을 적고, 다음 선택을 가르는 최소 비교만 설계한다.
- 결과물: (a) 유지할 서버 후보, (b) PC 결과가 지지하는 다음 수정, (c) 제외할 방향과 반례. 최종 성능 채택/제출 조건은 별도 유지한다.

## 4. 즉시 다음 작업
PC 실행을 기다리는 대신 기존 우수 정책 전체 보상 벡터와 실제 행동 손익을 비교해 서버 첫 조합 후보를 선정한다. 이 문서는 후보값 선정 완료나 실행 패키지 발행 완료가 아니다. 신규 패키지는 후보 선정·예산/TTL 확인 뒤 기존 발행 계약대로 만든다.

### 2. 계획 검토 — 실행 전에 바로잡을 점
1. **"우수 설정 조합"의 공간이 사실상 비어 있다 [확인].**
   - 원자료 근거: `tools/go2_excellent_reward_vectors.py`가 7개 정책(A033·A038·A043·A048·A049·A050·A055)의 학습 `env.yaml` 보상 11항을 직접 읽는다. 결과 `reports/evidence/go2_excellent_reward_vectors_20261001/REWARD_VECTORS.csv`에서 값이 갈리는 항은 `lin_vel_z_l2`·`ang_vel_xy_l2` 둘뿐이다(`DIFF_TERMS.txt`). 계약 테스트 `tools/test_go2_excellent_reward_vectors_contract.py` 3건이 통과했다.
   - A043과 A048의 전체 보상 벡터는 `lin_vel_z_l2`(−1.5 대 −1.25) 하나만 다르다. track 1.5, feet_air_time 0.2, ang_vel_xy −0.05, action_rate −0.01, flat 0이 같다.
   - 다른 우수 사례도 두 변수 안에 있다. 험지 옆걸음 상위 A038·A050, 험지 전진 A049, 밀침 A055가 그렇다. A038·A055는 ang_vel_xy −0.08이고, 나머지는 lin_vel_z 값만 다르다.
   - 그래서 A043에서 "계단"을, A048에서 "험지·밀침"을 가져오는 조합은 lin_vel_z 값을 고르는 일이 된다. 중간값 −1.375(A050)는 이미 10cm 계단이 무너졌다(≥2단 31, 판정 87). 남은 미시험 조합은 A048 + ang_vel_xy −0.08 하나이고, PC G-A057 행(`ang_vel_xy_l2_m0p08`)과 같은 설정이다.
   - 이 조합의 예측은 부정적이다. A043 위 같은 변경(A055)에서 험지 옆걸음 24→50, 15cm ≥2단 77→0, 밀침 3방향 악화가 나왔다. ang_vel_xy를 바꾼 세 번 모두 계단이 무너졌다(A038·A041·A055). 그래서 서버 첫 후보는 "조합"이 아니라 **A048 위 한 항 변경**이 된다(§2 순서 6의 "탐색 가설").
2. **서버 A048 자체가 단일 run의 끝값일 수 있다 [확인: 서버 lin_vel_z 여섯 run 중 끝값 / 추정: 운의 비중].**

   - 따라서 서버 후보가 서버 A048보다 낮게 나와도, 총점 하락만으로 그 변경의 악화라고 읽지 않는다. 판정은 사전등록한 표적·보호 지표로 한다.
   - "개선이면 보존" 규칙(§2 순서 5)도 같은 이유로 표적 지표가 사전등록 문턱을 넘은 경우로 한정한다.
3. **A043 출발선은 두 조건이 필요하다.**
   - 첫째, `lin_vel_z_l2` 고정 결정(2026-09-29, A048 기준 −1.25 해석은 사용자 확인 대기)이 A043의 −1.5를 출발 설정으로 허용하는지 사용자가 정해야 한다. 이 문서 §2는 A043을 출발 후보로 적었지만, 그 결정을 명시적으로 바꾸지는 않았다.

### 3. 반드시 포함할 상세안
1. 출발 보상 설정, 효과 비교 대상, 채택 판정 대조군을 분리한다. 보상 설정 재사용인지 checkpoint 이어 학습인지 명시한다. 기존 우수 정책의 공통값과 충돌값을 구분하고, 설정에 포함된 값 자체를 인과효과로 쓰지 않는다.
2. 실제 시험 이력에서 가져올 후보들을 비교하고 첫 실행 권고 하나와 같은 비용 대안을 정한다. 각 후보에 현재 약점, 바꾸려는 행동, 강좌 방향, 지지/반대 관측, 정확한 변경 전후 값과 유지값, 값/폭 이유, 보존할 이득을 적는다. 우수 설정에서 빌린 값과 새 탐색 가설을 구분한다. 기존 track1.4/ang-0.06 미승인안을 이름만 바꿔 되살리지 않는다. 다시 제안한다면 새 근거 또는 기존 오류 정정을 명시한다.
3. 첫 실행에서 학습 seed·iteration·평가 checkpoint·G1~G7 평가 구성·필수 영상·학습 report·회수 파일·판독 도구를 구체화한다. 평가 seed와 학습 seed를 구분하고 기존 도구/러너를 우선 재사용한다. 번호는 원장/upload 중복 확인 전 임의 확정하지 않는다.
4. 첫 결과에 따른 다음 실험을 개선/손익 교환/악화/불확실로 나누어 적는다. 각 분기에 유지할 설정, 다음에 바꿀 한 항과 이유, 추가 학습하지 않을 조건을 적는다. 미래 값의 근거가 없으면 선택 규칙으로 명시한다. 매회 기존 최선 설정과 비교하며 효과 합산을 가정하지 않는다.
5. 계단 ≥2단·도달 후 진행, 종료 시점·기울기·높이만 판정, 추종·정체를 분리한다. 험지 전진/옆걸음·우회전·밀침의 손익도 함께 판독한다. 사전등록 문턱을 결과에 맞춰 바꾸지 않는다. 새 탐색 기준은 실행 전에 수치와 이유를 적고 기존 채택 기준과 구분한다.
6. 서버 잔여 예산의 출처/시점을 확인하고 학습+평가+영상+회수 비용을 산정한다. PC의5일을 서버 예산으로 치환하지 않는다. 비용 미확인 항목은 명시하되 후보 분석은 계속한다. 첫 실험 비용, 다음 재평가 시점, 종료/회수 조건을 적는다.
7. PC 결과가 도착할 때마다 서버 다음 선택에 반영하는 규칙과 5일 뒤 통합 절차를 적는다. PC는 같은 PC 기준, 서버는 서버 기준으로 비교한다. 전진 추종 기준이 바뀌면 이전 다른 보상의 효과가 유지된다고 가정하지 않고 유망 조합만 후속 확인한다.

### S-3. PC 결과 없이 이어 가는 서버 경로 (R4)
**기존 자료로 방어할 수 있는 서버 후보는 둘이다.**

- S2: ang_vel_xy −0.05→−0.06

나머지 허용 항은 강좌 방향이 실패 경로와 반대이거나(action_rate 강화 "굼뜸", feet_air_time 하향 "등반약"), 이미 같은 방향의 손실이 관측됐거나(flat 강화, A047), 사용자 제외에 걸린다(상세안 §2-4). 그래서 S2 뒤에는 기존 자료로 고를 후보가 없다. **이 계획은 두 회차까지만 PC 없이 이어진다.** 그 뒤는 새 근거(PC 행, S1·S2 판독, 새 관측)가 생겨야 열린다. 이 한계를 숨기지 않는다.

**순서와 분기(PC 결과가 없어도 진행):**
1. **S1:** 서버 A048 보상 + track 1.4.
2. **S1 판독 후 S2의 출발 보상을 정한다(S-2 규칙):**

   - S1이 보존 후보이면 기준 승격과 관계없이 기록한다.
3. **S2를 열지 않는 경우:**
   - S1에서 계단 ≥2단(10·15cm)이 `WORSE_ALL_SEEDS`이고 표적이 SUPPORTED가 아닐 때다. 이 경우 같은 계단 위험을 더 무겁게 가진 ang 후보를 바로 이어 돌리지 않는다.
   - 대신 S1과 S2의 계단 위험을 다시 비교한 결과를 문서에 남기고 Codex가 정한다.
4. **S2 판독도 같은 계약(S-2)으로 한다.**

5. **방향별 중단(전체 중단과 분리):**

6. **전체 서버 튜닝 정지:** S-5의 실측 예산 조건에 닿을 때, 또는 열 후보가 없을 때다. 후보가 없어서 멈춘 것은 "후보 대기"로 적고, 예산 종료와 구분한다.

### S-6. Codex 전달용 요약 (문장)
R2와 R3은 코드에서 직접 확인했고 제 오류입니다. 보호 판정은 문턱 수가 아니라 세 seed 일치 악화(`WORSE_ALL_SEEDS`)만 보며, `--all`은 서버 A048 seed별 값과 비교합니다. 그래서 판독을 세 출력으로 나눴습니다. 사전등록 판정은 그대로 보존하고, 실제 변화량은 따로 적고, 채택 판정도 따로 적습니다. "손실 문턱 미도달"을 보존으로 쓰지 않습니다. 보존 후보와 기준 승격을 분리했고, 기준 승격 조건은 표적 SUPPORTED, `WORSE_ALL_SEEDS` 없음, 계단·우회전·밀침에서 잃은 로봇 수가 표적에서 얻은 로봇 수 이하라는 세 가지입니다. PC 층 비교는 같은 계수 함수로 PC A048 seed별 값과 나란히 적고, 판정 이름을 붙이지 않습니다.

R1은 받아들여 "제출 가능한 정책을 얻는다"는 선정 근거와 "확정 경로의 직접 방향"을 철회했습니다. 남은 근거로 다시 비교해도 S1을 앞에 둡니다. ang 강화는 같은 방향의 표적 결과가 기준에 따라 59→18과 24→50으로 뒤집혔고, A048은 A043보다 덜 흔들려 A055 쪽 결과를 배제하지 못합니다. 계단 반례도 3/3입니다. track 하향은 지지가 약하지만(종료 58→48) 표적 악화 관측이 없고, 계단 반례는 1/1입니다. 차이가 작다는 점과 순위를 바꿀 PC 관측 두 가지를 적었습니다.

R4는 받아들여, PC 없이 이어지는 경로를 S1 → S2(ang −0.06)로 적었습니다. S2의 출발 보상은 S1이 기준 승격 조건을 만족하는지에 따라 정합니다. 기존 자료로 방어할 수 있는 서버 후보는 이 둘뿐이고, 그 뒤는 새 근거가 필요하다고 한계를 밝혔습니다. "feet_air_time 0.35만이 계단 재개 경로"는 철회하고, 어느 행의 계단 개선도 탐색적 발견으로 보고하게 했습니다.

R5는 예산을 실측 잔여·필수 비용·선택 비용으로 나누고, 최종 학습 예약분 자동 중단을 없앴습니다. report 누락은 복구 가능과 복구 불가로 나눴고, 전체 종료 규칙은 방향별 중단과 예산·후보 부재 정지로 바꿨습니다. 코드·사전등록·ZIP 변경과 서버 실행은 없습니다.

### 1. PC1과의 역할 분담
- **PC1:** G-A057 목록·값·순서·사전등록 그대로다. A048 위 한 항 변경 12행이고, 다음 행은 track 1.4, 그 뒤 track 1.6, ang −0.04, ang −0.08, feet_air_time 0.01·0.1·0.35, action_rate −0.008·−0.012, flat −0.25·−0.5 순이다 [확인, `sweep_order.txt`]. PC1의 행·문턱은 PC2 결과로 바꾸지 않는다.
  - PC1 속도는 한 행 약 9시간이다(RTX 3050). A058 행 3 처리에 따라 G-A057 재개 시점이 달라진다 [모름]. 남은 11행은 약 99시간이라 5일 안에 다 오지 않을 수 있다.
- **PC2:** 고정 목록을 복제하지 않는다. 자체 기준선을 먼저 확보하고, 결과에 따라 다음 한 항 또는 조합을 고른다.
- **왜 PC2 첫 후보가 PC1 목록과 겹치는가 — 제약 안의 후보 공간 [확인 + 추정]:**
  - 출발 보상은 A048이다. `lin_vel_z_l2`가 −1.25 고정이라 A043·A050·A038 같은 다른 우수 설정은 출발점이 될 수 없다.
  - A048 위에서 강좌·배포 방향 근거가 있는 한 항 변경은 track 하향, ang_vel_xy 강화, feet_air_time 상향, flat 강화, action_rate 강화다. 앞의 넷과 action_rate는 이미 PC1 목록에 있다.
  - 목록 밖 항은 근거가 없다. dof_torques·dof_acc는 강좌 방향 근거가 없고, track_ang_vel_z는 A048에 표적(우회전 낙상 0)이 없다.
  - 따라서 제약 안에서 PC2가 PC1과 겹치지 않는 길은 두 가지뿐이다. 하나는 PC1 단일 결과가 나온 뒤의 **조합**이고, 다른 하나는 **사용자 제약을 넘는 항**이다. 첫 실행에는 어느 쪽도 쓸 수 없다. 그래서 첫 후보는 목록과 같은 설정이 되고, 중복의 목적을 아래(§3)에 밝힌다.
- **장비 간 중복의 목적:** 같은 보상의 효과를 두 장비에서, 각자의 A048 기준과 비교해 두 번 읽는 것이다. 서버 대 PC1의 A048 차이가 대부분의 보상 쌍 차이만큼 컸으므로, 한 장비 한 run만으로는 효과와 학습 경로 차이를 나눌 수 없다. 이것은 학습 seed 반복(U2)이 아니다. seed는 42 그대로이고, 장비가 다르다.
  - 단순 중복 sweep과의 구분: PC2는 PC1 목록 중 다음 결정(§4의 조합)에 필요한 행만 하나씩 고른다. 목록 전체를 돌지 않는다.

**2-2. smoke와 속도 측정 (상한 각 15분)**
- 인계 §4-1·4-2를 그대로 한다. 64 env 3 iter, 이어서 4096 env 2 iter.
- 4096 env가 메모리 부족이면 멈추고 보고한다. 로봇 수는 줄이지 않는다.
- iter당 시간 t를 잰다. 예산은 이 값으로만 잡는다(§6). PC1의 9시간이나 서버 95분을 가져오지 않는다.

**2-3. 평가층 확인 — 고정 정책 평가 (추가 비용 없음)** [확인, 새 도구]
- 모든 run은 같은 G-A033 정책을 5 case(seed 101·202) 평가한다.
- 서버 run 10개끼리는 5 case 모두 같은 값이었다. PC1 run 3개끼리도 같은 값이었다. 장비 안에서 평가는 반복해도 같다.
- 서버와 PC1 사이는 조금 다르다. 험지 옆걸음 자세 낙상 20 대 19(32대 중), 험지 전진 1 대 2, 평지 전진·경사·DR은 낙상 같음, 속도 차이 0.02 m/s 이하다.
- 따라서 서버 A048과 PC1 A048의 큰 차이(험지 옆걸음 16 대 68/96)는 평가가 아니라 **학습 경로**에서 생겼다. 같은 장비에서 같은 보상·seed로 두 번 학습했을 때 같은 정책이 나오는지는 잰 적이 없다 [모름].
- PC2 판정: B1의 sentinel 5 case를 서버·PC1 값과 나란히 적는다. 험지 옆걸음 낙상이 19~20, 험지 전진 낙상이 1~2 밖이면 PC2 평가층이 다르다고 표시한다. 그때만 서버 A048 정책(iter 900)을 PC2에서 69 case 평가한다(평가 전용, 학습 없음). 이 범위는 이번에 새로 정한 탐색용 확인이며 채택 기준이 아니다.
- 평가 전용 검사와 같은 보상의 재학습은 서로 다른 확인이다. 앞의 것은 평가 환경의 차이, 뒤의 것은 학습까지 포함한 차이를 본다. 하나로 다른 하나를 대신하지 않는다.

**2-4. 기준선 B1 — PC2 A048 seed 42 새 학습**
- 보상: A048 `env.yaml` 그대로(G-A058 행 1과 같은 바이트). 학습 seed 42, 4096 env, 1000 iter, 평가 checkpoint iter 900 고정, 69 case(평가 seed 101·202·303), 영상 10편, report.html 보존.
- 필요한 이유: PC2에서 A048 출발 후보를 읽을 직접 비교 기준이 이것뿐이다. 서버 A048이나 PC1 A048은 학습 경로가 달라 PC2 후보의 대조군이 될 수 없다(§2-3).
- 덤으로 얻는 것: 같은 보상·seed의 A048 학습이 장비 셋(서버·PC1·PC2)에서 나온다. 범위는 적되 1회씩이라 변동 폭을 추정했다고 쓰지 않는다.
- B1은 한 번만 한다. 기준선을 반복하는 캠페인으로 만들지 않는다.
- B1이 정지(moving gate STATIONARY)거나 run이 불완전하면 PC2 후보 판독을 하지 않는다. 원인 기록 → 사용자·Codex 보고 → 그 뒤 결정이다.

### 3. 첫 후보 선택과 대안 비교
**C1 = A048 보상 + `ang_vel_xy_l2` −0.05→−0.08 (탐색, 확신 낮음)**
- **현재 약점 [확인]:** 험지 옆걸음이다. 서버 A048에서 G3 8.98/14로 남은 점수가 가장 큰 블록이고 낙상 16/96이다. PC1 A048에서는 G3 2.18/14, 낙상 68/96으로 더 크다.
- **실패 과정 [확인 기록, 다시 분석하지 않음]:** G-A056(A043 진단)에서 넘어지는 쪽 발 안쪽 배치 → 반대쪽 하중 상실 → 옆으로 구름. 기울기 증가 앞에 옆 속도 변화가 먼저 보인 사건이 판독 가능한 11대 중 8대다.
  - 설명되지 않은 것: 발을 왜 안쪽에 딛는지, 왜 회복하지 못하는지. A048의 남은 낙상이 같은 경로인지는 로봇 단위로 확인하지 않았다.
- **강좌·배포 예측:** ang_vel_xy "몸통을 기울이지 마라 / 강하게: 덜 휘청(안정)", 생성기 "흔들림 억제 ↑ 안정". 이 항의 식은 몸통 roll·pitch 각속도를 벌한다. 실패 과정의 마지막 단계(옆으로 구름)에 직접 걸린다. 발 안쪽 배치라는 앞 단계를 겨누는 것은 아니다.
  - 경쟁 설명(같은 항): "약하게: 흔들림 허용(험지 적응 여지)". 강화가 필요한 몸통 움직임까지 막아 험지 대응을 해칠 수 있다는 예측이다.
- **지지 관측 [확인]:** A033 기준 −0.05→−0.08에서 험지 옆걸음 낙상 59→18(A038). 사용자 관찰(2026-09-29): 강하게 할수록 험지 낙상이 준다. 수치는 −0.04 52, −0.05 59, −0.08 18(A033 계보, 1단계)이라 앞의 두 점은 순서가 반대다.
- **반대 관측 [확인] — 그대로 남는다:**
  - A043 기준 같은 변경(A055)에서 험지 옆걸음 24→50, 험지 전진 6→12, 밀침 3방향 악화.
  - ang_vel_xy 변경은 걷는 기준선에서 계단을 세 번 모두 잃었다(A038 10cm ≥2단 43→0, A041 43→8, A055 15cm 77→0).
- **기준에 따라 뒤집힌 이유에 대한 가설 [추정, 검증 안 됨]:** 지지 사례의 기준(A033)은 험지 옆걸음 낙상이 많았고(59), 반대 사례의 기준(A043)은 적었다(24). PC A048(68)은 앞쪽과 비슷하다. 이것은 기준 상태가 비슷하면 반응도 비슷하다는 예측일 뿐이다. 흔들림 크기나 낙상 수가 비슷하다는 것만으로 반응을 보장하지 않는다(Codex 결정 1). C1의 결과가 이 가설을 시험한다.
- **값·폭의 이유:** −0.08은 새 탐색값이 아니다. 우수 정책 A038·A055의 벡터에 있던 값이고 강좌 Go2 실습 기본값이다. A048(−1.25)과 −0.08의 조합은 우수 벡터 7개 안의 미포함 조합 중 하나다. 최적값이라는 근거는 없다. −0.06은 서버 S2로 철회된 값이라 쓰지 않는다. −0.04는 사용자 제외다.
- **유지값:** track 1.5, feet_air_time 0.2, lin_vel_z −1.25, action_rate −0.01, flat 0, 나머지는 A048 그대로.
- **보존할 이득(PC2 B1 기준으로 읽음):** 우회전 낙상, 밀침 4방향, 험지 전진 낙상·속도, 평지 전진 속도, 계단 10·15cm ≥2단과 도달 후 진행. B1 값이 나오기 전에는 수치를 정하지 않는다. 참고로 PC1 A048은 우회전 0, 밀침 10/384, 험지 전진 6·0.36 m/s, 10cm ≥2단 76, 15cm 6이었다.
- **PC1 목록과의 중복:** PC1 행 `ang_vel_xy_l2_m0p08`과 같은 설정이다. 목적은 §1의 장비 간 재현과, §4의 조합 판단(track 1.4 + ang −0.08)에 필요한 두 단일 결과를 PC 층에서 빨리 갖추는 것이다. PC1은 track 1.4를 다음으로 돌고 ang −0.08은 네 번째에 돈다. PC2가 ang −0.08을 먼저 하면 두 험지 레버의 PC 층 단일 결과가 가장 빨리 갖춰진다.

**같은 비용의 대안과 순서:**
1. **A048 + track 1.5→1.4 (2순위).** 같은 험지 표적이고, 겨누는 단계는 몸이 지지를 앞지르는 앞 단계(간접 가설)다. PC1이 바로 다음 행으로 돈다. PC2가 같은 행을 먼저 하면 두 장비가 같은 레버를 비슷한 때 읽게 되고, 다른 레버(ang)는 PC1 네 번째 행까지 비어 있다. 서버 S1을 PC 대수가 늘었다는 이유로 되살리는 것이 아니다. §4 분기에서 PC1 결과를 보고 PC2에 넣을지 정한다.
2. **A048 + feet_air_time 0.2→0.35.** 계단 실패 원인(발을 단 높이로 들지 못함, 평소 발 최고점 약 0.12 m)에 강좌가 직접 가리키는 유일한 레버다("발 높이 ↑ 등반 유리"). 그러나 사용자 기각(0.25, 2026-09-28)이 있고, 2026-09-29의 탐색 범위 해제는 G-A057(PC1) 범위로 기록됐다(인계 §8). PC2로 넓힐지는 사용자 결정이라 첫 후보로 쓰지 않는다. 반례 A015(Pilot-01 기준 0.35에서 몸 낮춤·평지 밖 붕괴)도 그대로다.
3. **flat 강화, action_rate 강화:** 강좌 방향이 실패 과정과 맞지 않거나(action_rate 강화 "굼뜸" — 지지 갱신이 늦는 실패와 반대) 같은 방향의 손실이 관측됐다(flat −0.5, A047 계단 소실·험지 옆걸음 59→60). PC1 결과로만 본다.
- **C1의 주된 위험:** 사용자 목표의 계단이다. ang 변경의 계단 소실 3/3이 A048 위에서도 나오면 C1은 험지와 계단의 교환이 된다. 이 경우 기준으로 올리지 않는다(§4).

### 4. 결과별 후속 실험 (PC2)
**판독 정의 — 실행 전에 등록, 탐색용이며 채택 기준이 아니다:**
- 직접 대조군: C1은 PC2 B1이다. 비교 출발 보상이 바뀌면 직접 대조군도 그 출발 보상의 PC2 run으로 바꾼다.

**분기:**
1. **개선 — 표적 방향 지지 + 보호 손실 관측 없음 + 정지 아님.**

3. **악화·무변화 — 표적 반대, 또는 혼재이면서 합이 B1 이상.**
   - PC2·A048 기준에서 ang 강화 방향은 닫는다. 인접값으로 자동 이동하지 않는다. PC1 ang −0.08 행이 오면 두 장비의 방향을 나란히 적는다.
   - C2는 분기 2의 track 1.4 조건을 따른다. 조건이 안 되면 계단 질문으로 간다.
4. **불확실 — 혼재이면서 합이 B1보다 작음.**
   - 수를 그대로 보고한다. C1을 기준으로 올리지 않고, 조합(C1 + track)도 만들지 않는다.
   - PC1 ang −0.08 행이 오면 두 장비 결과를 함께 보고 분기 1~3 중 하나로 다시 분류한다. 그 사이 PC2는 분기 2의 track 1.4 조건을 확인해 해당하면 그것을 돌린다.
